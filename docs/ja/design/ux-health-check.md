# Studio の UI/UX 通し点検（2026-11-07、v0.1.8＋#133）

英語版が正です（[docs/design/ux-health-check.md](../../design/ux-health-check.md)）。

この 2 日で 40 本以上の PR が別々に入り、Studio を一人の目で頭から通して見ていなかった。そこで本物の Studio（Tauri 本体、Linux 上で WebDriver から操作）を空のワークスペースで起動し、使う人の流れを順に歩いた。前提は「AI で作る」と「手でゼロから組む」の両方が一級の入口であること。

照らした決まりは [ui-principles.md](../../design/ui-principles.md)、[wording.md](../../design/wording.md)、灰色は濃いめ・ダークはスレート、日本語字形。直すのはこの文書の範囲外で、ただし Studio が落ちる不具合 1 件だけは同じ PR で直した（下の U1）。

スクショ：プロジェクトのファイルの `shikigami/ux-health-check/`（以下の `[12]` は `12-palette.png` などの番号）。

## 歩いた流れ

| # | 流れ | 歩いた内容 | 結果 |
|---|---|---|---|
| 1 | 初回起動・AI の準備 | 新しいホームで起動 → 言語 → AI ペイン | 動く。最初の画面が AI 前提 [01][02] |
| 2 | AI で 1 本作る | 「AI の答えを貼り付け」で見本の答えを取り込み → 開く → 確認待ち | 取り込みは動く。**確認待ちに出ない** [25][46] |
| 3 | 手でゼロから組む | 新規作成 → 表を行ごとに読む → 繰り返し → ログ出力 → 使える値から挿入 | 組める。最初の 10 分にひっかかりが多い [10]〜[22] |
| 4 | 試す・確かめる | ノードの単体実行、実行、ファイルが無いエラー、検証結果、手順書、変数 | 動く。言葉と見た目の揺れが多い [17][23][30]〜[33] |

| 6 | 確定・配る | 確定、実行画面、自動実行（スケジュール） | **実行画面の「実行」で Studio が落ちる**（修正済み）[40][41][50][51][70] |

歩けなかったもの：AI ペインでの実際の会話（この環境にサインイン済みの AI が無い）、「画面から選ぶ」（ブラウザ・デスクトップの実機が要る）、Windows だけの部分（ファイル選択ダイアログ、タスクトレイ、時刻欄の表示）。

## よかったところ

- パレット：「よく使う」から開く、かな検索（「くりかえし」）、追加する場所の一文 [12][18]。
- 繰り返しを足すと、リストに前のノードの結果（rows）が自動で入る [19]。
- ノードの画面の「使える値」：繰り返し中の行の列（取引先・メール・金額）が出て、押すと欄に入る [21][22]。
- ノードの単体実行の結果が表で出る [17]。プロジェクトの棚がファイルの使われ方（「どのノードも使っていません」）を出す。
- 日本語字形（Noto Sans JP）、ダークはスレートで読みやすい [80]。

## 見つけたこと（画面ごと）

区分：**壊** 動かない・導線が切れる／**要** 要るのに無い／**不** 要らない・ノイズ／**迷** 迷う／**重** 同じものが二か所／**揺** 用語の揺れ。

### フローの一覧・初回 [01][02][10]
- 要：最初の画面の入口が AI だけ。空の一覧は「AI にフローの作成を依頼することもできます」、見本の説明も「AI に依頼して…」。手で組む人への最初の一歩（最初のノードの候補、見本を開いて真似る）が無い。
- 要：スプラッシュ画面は無く、要らない。足りないのは初回の空状態の案内。
- 重：「AI の答えを貼り付け」が一覧の見出しと AI ペインの二か所 [02]。
- 迷：AI ペインを開くと見出しの「新規作成」が 2 段目に落ちる [02]。
- 不：「新規作成」と「作成」の塗りのボタンが同じ面に二つ [10]。
- 揺：AI ペイン「Claude Code を導入する」「未導入」「AI をこの PC に入れて」→ wording.md は「インストール」。

### フロー図（手で組む）[11][13][19][23]
- 迷：ノードを足した直後に赤い「エラー 1 件」が出て実行が押せない [13]。足したばかりのノードは「未設定」と見せたい。一方ログ出力は必須の欄が空でも「検証OK」[21]。同じ状態で表示が違う。
- 迷：足したあと設定するには「設定を開く」をもう一度押す。足した直後にノードの画面を開くか、必須の欄だけをその場で出したい。
- 不：結果の変数が自動でプログラム名になる（`rows`、繰り返しの結果 `forEach`）。`forEach` はどのノードも読まず、変数一覧で警告になる [32]。
- 揺：プログラム名が画面に出る。ノードの文に `path`、見出しの `forEach` タグ、線のラベル「forEach：rows の 1 件ずつ」、インスペクターの「変数のつながり」の `excel.readRows`・`control.forEach`、ステータスバーの `excel.readRows` [16][19][30]。
- 揺：繰り返しが「繰り返し（リスト）」「回数ループ」「条件ループ」と混在。パレットで「くりかえし」を探すと先頭が「次の繰り返しへ」、英語のタグ（continue・forEach・repeat・while）も出る [18]。
- 迷：選んだノードの操作（↑ ↓ まとめる…）がインスペクターの下に切れる。フロー図が作業面の中央に来ず、実行後に図の位置が飛んでドックがノードに重なる [19][23]。
- 不：右下の「React Flow」の透かし。

### ノードの画面 [14][16][17][21][22]
- 重：「フロー図に戻る」と「閉じる」の二つの出口。塗りのボタンが「閉じる」（主の操作が閉じる）。
- 揺：中央の列の見出し「設定」の中にまた「設定」の節。「JSON で編集（上級）」は開発の言葉。
- 揺：「値を入れたい欄を先にクリックしてください」（入れる）。パスの説明が「相対パス・絶対パス」。
- 不：「使える値」にそのノード自身の結果（rows）が「ほかの変数」として出る [14]。
- 迷：テンプレートが欄に `{{ item.取引先 }}` のまま出る。見出しの文ではチップになるのに、欄は生の構文 [22]。
- 要：ループの中のノードは、一度フロー全体を実行するまで「ノードの単体実行」が押せない。前のノードの単体実行の結果を使えるとよい [22]。
- 不：単体実行の表に内部の列 `_row` [17]。

### パレット [12][18][20]
- 揺：説明文に禁止語（「入力欄に文字を入れる」「クリップボードに入れる」「残りを飛ばして」）。
- 迷：繰り返しの中から開くと、パレットがインスペクターに重なって右にはみ出す [20]。

### 実行・エラー [23][30][31][33]
- 揺：実行ログに `run_01a1…`、ノード ID `stp_5993f49d`、「(rev 7)」が出る [23]。
- 揺：一時停止パネルにエラーコード `FILE_NOT_FOUND`、「英語の原文」、関係ない英語「画面を取得できませんでした：'path' is required」[30]。
- 揺：タイトルバーは「停止」、パネルは「中止」。中止したのにログの最後は「失敗 (22386 ms)」[31]。
- 不：パネルに塗りのボタンが二つ（再実行・AI に修正を依頼）。パネルが作業面の半分を覆い、止まったノードがドックの下に隠れる [30]。
- 揺：同じ仕組みに「検証OK / エラー n 件」「手直し n 件」「要手直し」「検証結果」の呼び名 [30][33]。
- 迷：手直しの説明「AI には画面やログイン情報が見えないため…」が、手で組んだフローでも出る。ファイルが無いとき、フォルダーにある `受注一覧.xlsx` を候補に出さない [33]。

### 確認待ち・AI の変更 [24][25][45][46][27]
- **壊**：AI が新しく作ったフローが確認待ちに出ない。貼り付けのダイアログは「AI からの確認事項が 1 件あります。「確認待ち」で回答してください」と言うが、確認待ちは「確認待ちはありません」「このフローは確認済みです」[25][46]。原因：確認待ちは元に戻せる変更（`isRevertible`）だけを数え、作成（`create`）は除かれる。MCP の `create_flow` も中身ごと作れるので同じことが起きるはず。AI の確認事項（checks）に答える場所が無くなる。
- **壊**：確認待ちの手直しの「部品を開く」が何も開かない（右が確認パネルなので部品を出す場所が無い）[27]。フローの場所では開く [28]。
- 迷：AI が一度も触っていない手作りのフローでも「このフローは確認済みです」[45]。
- 揺：「AIからの変更」（空白なし）。

### 部品 [28]
- 迷：部品の編集がインスペクターにある（インスペクターは読むだけの決まり）。項目名「種類・名前・ラベル・表示の文字」は UI オートメーションの言葉で、「キー searchBox」も出る。主の操作「画面から選ぶ」が小さな文字リンク。

### 確定 [40][41]
- 要：手直しが残っていても、最後の実行が失敗でも、注意なしに確定できる。
- 迷：「確定」と「版」が同じダイアログで、塗りのボタンが二つ。「v1「v1」を確定済み」の重複。版の行に「rev 7・3 steps」（英語と開発の言葉）。
- 不：「v1 を確定しました」の帯が、別の場所に移ってもずっと残る [50][60][61]。

### 実行画面 [70]
- **壊**：「実行」を押すと Studio ごと落ちる。`runner_run` が同期のコマンドで、Tokio の外で実行を始めて panic → abort する。Windows でも同じ（Tauri の同期コマンドはメインスレッドで動く）。**この PR で修正**（`async fn` に）。
- 迷：一覧の「たった今 失敗」は Studio での試し実行の結果で、確定版の実行と混ざっている。

### 自動実行 [50][51]
- 迷：スケジュールが一つも無いのに赤い「エージェントは停止中です」。「エージェント」は開発の言葉。
- 要：タイトルバーに場所の名前が出ない（`TitleBar` の `PAGE_TITLE` に runs が無い）。実行履歴（ui-principles の予定）はまだ無い。
- 迷：確定していないフローもスケジュールの選択肢に並ぶ。入力の欄名が変数名 `orderNo`。保存先 `schedules.json` のフルパスを出す。
- 揺：フォームが名前を上に積む形で、設定の「1 設定 1 行」と違う。ボタンの順が「キャンセル｜保存」で、シークレットは「保存｜キャンセル」[63]。

### 設定 [61][62]
- **壊**：目次の印がずれる（どこを読んでいても「バージョンと更新」）。
- **壊**：AI の節「下の「導入する」を押すと、この場で入れてサインインできます」— 下にボタンが無い（インストールは AI ペインだけ）。
- 揺：AI の呼び名がサイドバー「Claude Code」、設定「AI エージェント」「使う AI」の三つ。
- 迷：「実行の許可」の中に「このフロー（受注を検索する）」の節。フローの設定が全体の設定に混ざる（ui-principles はインスペクターのフロー表示）。「保存」がどこまで効くか見えない。
- 揺：許可の説明に `browser.open・oauth.signIn・http.request`。

### シークレット [60][63]
- 小さな揺れのみ（「MFA の設定キー」「otpauth://」）。ボタンの順は上記。

### 全体
- 不：一つの面に塗りのボタンが複数（タイトルバーの実行＋ドックのノード追加＋インスペクターの「変数を追加」など）[11]。
- 迷：「実行の設定」の「既定のタイムアウト (ms)」「エラー時（既定：停止する）」— ミリ秒と「停止」[11]。
