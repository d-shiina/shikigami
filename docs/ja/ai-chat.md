# MCP を使えない AI のチャットでフローを作る

[English](../ai-chat.md) | 日本語

職場で使える AI が Microsoft Copilot などに限られ、SpellSheet の MCP サーバーにつなげない場合でも、AI にフローを書いてもらえます。フローの形式・すべてのノード・すべての関数を書いた仕様書を AI に読ませると、AI は JSON で答えます。その答えを Writer に貼り付けると、Writer が検証して開き、あなたが手直しする必要のあるところを示します。

AI が何かを実行することはなく、画面やパスワードを見ることもありません。取り込んだ内容は作業中の内容として保存され、人が確認して確定するまで無人実行には使われません（[policy.md](policy.md)）。

## 1. AI に仕様書を渡す

仕様書は 2 つのファイルで、この PC に入っているノードから作られます。

| ファイル | 中身 | 入れる場所 |
| --- | --- | --- |
| `shikigami-ai-instructions.md` | 答え方（8,000 文字未満） | エージェントの指示 |
| `shikigami-ai-reference.md` | フローの形式、ノードごとのパラメーターと例、関数 | ナレッジ（添付ファイル） |

Writer の「フロー」ページの **AI の答えを貼り付け** › **仕様書を保存** で保存できます（保存先は `ダウンロード\SpellSheet AI 仕様書`）。コマンドラインなら次のとおりです。

```
spellsheet ai-guide --dir <フォルダー>
```

組み込みのノードだけの版は [docs/ai/](../ai/) にもあります（SpellSheet をまだ入れていない人向け）。ノードのプラグインは、自分の PC で保存したファイルにだけ載ります。

- **Microsoft Copilot Studio のエージェント**：エージェントの指示に `shikigami-ai-instructions.md` の中身をすべて貼り付け、ナレッジに `shikigami-ai-reference.md` を追加します。以後、エージェントを使う人は誰でもそのままフローを依頼できます。
- **エージェントを作れないチャット**：会話の最初に 2 つのファイルを添付し（または指示を貼り付けて詳細を添付し）、それに従うよう依頼します。詳細は長いため、添付の一部しか読まないチャットではノードを見落とすことがあります。詳細をナレッジに入れたエージェントのほうが確実です。

SpellSheet を更新したときやプラグインを入れたときは、仕様書を保存し直して AI のファイルを入れ替えてください。

## 2. フローを依頼する

自動化したいことを普通の言葉で伝えます（使うサイトやアプリ、作業の順番、読み書きするファイル）。AI は必要なことを質問し、JSON のブロック 1 つ（「答え」：要約、あなたへの確認事項、フロー）で答えます。

AI は画面を見られないので、ボタンや入力欄を推測で書きません。それぞれを **部品** として名前を付け、どこにあるか（「画面右上の『保存』ボタン」など）を書きます。どの要素かは Writer であなたが指定します。パスワードも書かず、ログイン情報の名前だけを書きます。登録は Writer で行います。

## 3. 答えを Writer に貼り付ける

**AI の答えを貼り付け**（フローのページ、AI ペインの上端、フロー図の右クリック）を開き、AI の返答をそのまま貼り付けて **取り込む** を押します（前後の文章が含まれていても構いません）。新しいフローとして追加するか、開いているフローの内容を置き換えるかを選べます（置き換えても「元に戻す」で戻せます）。

- **読み取れないとき**（JSON が壊れている、知らない項目があるなど）は、何も変更しません。**AI に返す文面をコピー** を押してチャットに貼り付けると、問題点の一覧と、答え全体をもう一度返す依頼が AI に伝わります。
- **取り込めたとき** は、2 つの一覧が出ます。
  - **手直しが必要なところ**：あなたにしかできない作業で、それぞれにボタンがあります。「画面から選ぶ」（部品を開き、「画面から選ぶ」で要素をクリック）、「ログイン情報を登録する」（名前を入れた状態で登録フォームを開く）、「フローのフォルダーに置く」（フォルダーを開く）。あなたを待っているノードにはフロー図で **要手直し** の印が付き、タイトルバーに件数が出ます。済んだものは一覧から消えます。
  - **AI に修正を依頼するところ**：フローの書き方の誤り（必須のパラメーターがない、存在しないノードなど）です。**AI に返す文面をコピー** を押すと、問題点と今のフローがコピーされます。チャットに貼り付け、返ってきた答えをもう一度取り込みます。

AI の要約と確認事項は、MCP でつないだ AI の変更と同じく **確認待ち** に入ります。確認事項に答え、試し実行をしてから確定してください。

## 4. AI にフローを直してもらう

今あるフローを AI に直してもらうときは、フロー図を右クリックして **AI に渡す用にコピー** を選びます（貼り付けのダイアログにも同じボタンがあります）。フローと答え方の説明がコピーされるので、チャットに貼り付けて直してほしいことを書き、返ってきた答えを「開いているフローの内容を置き換え」で取り込みます。AI はノードの ID とあなたが選んだ部品をそのまま残すので、確認待ちには変わったところだけが出ます。

## 答えの形式

```json
{
  "format": "shikigami.answer",
  "summary": "受注一覧を検索する\nログインし、注文番号で検索します。",
  "checks": ["検索するのは注文番号でよいですか？"],
  "flow": {
    "name": "受注を検索する",
    "parts": { "searchBox": { "label": "受注一覧の上の検索欄", "app": "browser" } },
    "steps": [
      { "type": "browser.open", "params": { "url": "https://example.com/orders" } },
      { "type": "browser.fill", "params": { "target": { "part": "searchBox" }, "value": "{{ orderNo }}" } }
    ]
  }
}
```

`target` のない部品は、人が画面から選ぶのを待っている状態です（`PART_NOT_PICKED`）。選ぶまでその部品を使うノードは検証を通らないため、推測の入ったフローが実行されることはありません。Writer は答えの形でない、フローだけの JSON（`{ "name": …, "steps": [ … ] }`）も取り込めます。
