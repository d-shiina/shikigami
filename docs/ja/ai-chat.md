# MCP を使えない AI のチャットでフローを作る

[English](../ai-chat.md) | 日本語

職場で使える AI が Microsoft Copilot などに限られ、SpellSheet の MCP サーバーにつなげない場合でも、AI にフローを書いてもらえます。Writer が依頼の文面（答え方の指示・今のフロー・あなたの依頼）をまとめてコピーし、AI のチャットを開きます。AI の答えを Writer に戻すと、Writer が検証して取り込み、変わったところと、あなたが手直しする必要のあるところを示します。

AI が何かを実行することはなく、画面やパスワードを見ることもありません。取り込んだ内容は作業中の内容として保存され、人が確定するまで無人実行には使われません（[policy.md](policy.md)）。

## 0. 使っている AI を選ぶ

Writer の AI チャットを初めて開いたとき、この PC に Writer から動かせる AI（Claude Code など）が無ければ「ふだん使っている AI はどれですか」と聞きます。AI の名前で選ぶだけで、MCP を使えるかどうかは Writer が判断します。

- **Microsoft Copilot**：会社のアカウント（Microsoft 365 Copilot）か個人のアカウントかを選びます。どちらもチャットにコピーして使います。
- **ChatGPT・Gemini・Claude**：ブラウザーやアプリのチャットで使っているか、PC にインストールする版（Codex・Antigravity・Claude Code）かを選びます。インストールする版なら Writer が AI を動かし、AI が画面を調べて試しながらフローを作ります。
- **GitHub Copilot・Cursor**：Writer が動かします。
- **わからない**：この PC に入っている AI があればそれを、無ければチャットにコピーする方法を使います。

あとから **設定 → AI** の「AI とのつなぎ方」で変えられます。

## 1. 依頼する

AI チャットの欄に、自動化したいことを普通の言葉で書きます（使うサイトやアプリ、作業の順番、読み書きするファイル）。**コピーして Microsoft 365 Copilot を開く**（選んだ AI の名前が出ます）を押すと、依頼の文面がコピーされ、AI のチャットがブラウザーで開きます。チャットに貼り付けて送ってください。フローを開いているときは、そのフローの今の中身も文面に入るので、「件名も書いて」のような直しの依頼もそのまま書けます。

新しいチャットでは最初に一度、仕様書 `spellsheet-ai-reference.md`（フローの形式、ノードごとのパラメーターと例、関数）を添付してください。チャット欄の **仕様書のファイルを開く** で保存先のフォルダー（`ダウンロード\SpellSheet AI 仕様書`）が開きます。仕様書はこの PC に入っているノードから作られ、プラグインも載ります。

AI は画面を見られないので、ボタンや入力欄を推測で書きません。それぞれを **部品** として名前を付け、どこにあるか（「画面右上の『保存』ボタン」など）を書きます。どの要素かは Writer であなたが指定します。パスワードも書かず、ログイン情報の名前だけを書きます。登録は Writer で行います。

### Copilot Studio のエージェントに入れておく

毎回添付する代わりに、Microsoft Copilot Studio のエージェントに仕様書を入れておけます。**設定 → AI → 仕様書を保存**（コマンドラインなら `spellsheet ai-guide --dir <フォルダー>`）で 2 つのファイルを保存し、エージェントの指示に `spellsheet-ai-instructions.md` の中身をすべて貼り付け、ナレッジに `spellsheet-ai-reference.md` を追加します。組み込みのノードだけの版は [docs/ai/](../ai/) にもあります。SpellSheet を更新したときやプラグインを入れたときは、保存し直して入れ替えてください。

## 2. 答えを Writer に戻す

AI の答えをコピーして Writer に戻ると、クリップボードに答えがあれば **クリップボードから取り込む** が出ます（答えを待っている間だけ、Writer に戻ったときに確かめます。設定 → AI で止められます）。チャット欄に貼り付けて **取り込む** を押しても構いません。前後の文章が含まれていても読み取ります。AI が JSON にコメントや末尾のカンマを付けていても読めます。

- **取り込めたとき** は、フローを開き、次の 3 つを出します。
  - **変わったところ**：追加・変更・削除したノード。
  - **あなたの作業**：あなたにしかできない作業で、それぞれにボタンがあります。「画面から選ぶ」（部品を開き、「画面から選ぶ」で要素をクリック）、「ログイン情報を登録する」（名前を入れた状態で登録フォームを開く）、「フローのフォルダーに置く」（フォルダーを開く）。済んだものは一覧から消えます。
  - **AI に修正を依頼するところ**：フローの書き方の誤り（必須のパラメーターがない、存在しないノードなど）です。**修正の依頼をコピー** を押してチャットに貼り付け、返ってきた答えをもう一度取り込みます。
- **読み取れないとき**（JSON が壊れている、知らない項目があるなど）は、何も変更しません。**修正の依頼をコピー** でチャットに戻します。
- **答えが途中で切れているとき**（長い答えをチャットが途中で止めたとき）は、**続きの依頼をコピー** を押してチャットに貼り付けます。返ってきた続きを取り込むと、前の答えとつなげて読みます。

AI の要約と確認事項は、MCP でつないだ AI の変更と同じく **確認待ち** に入ります。確認事項に答え、試し実行をしてから確定してください。

別の場所で始めたチャットの答えを取り込むときは、AI チャットの上端、フローのページの **新規作成** の横、フロー図の右クリックの **AI の答えを貼り付け** を使います。

## 答えの形式

```json
{
  "format": "spellsheet.answer",
  "summary": "受注一覧を検索する\nログインし、注文番号で検索します。",
  "checks": ["検索するのは注文番号でよいですか？"],
  "flow": {
    "name": "受注を検索する",
    "parts": { "searchBox": { "label": "受注一覧の上の検索欄", "app": "browser" } },
    "steps": [
      { "type": "browser.open", "params": { "url": "https://example.com/orders" } },
      { "type": "browser.fill", "params": { "target": { "part": "searchBox" }, "value": "{{ orderNo }}" } }
    ]
  }
}
```

`target` のない部品は、人が画面から選ぶのを待っている状態です（`PART_NOT_PICKED`）。選ぶまでその部品を使うノードは検証を通らないため、推測の入ったフローが実行されることはありません。Writer は答えの形でない、フローだけの JSON（`{ "name": …, "steps": [ … ] }`）も取り込めます。
