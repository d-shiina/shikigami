# 画面から部品を選ぶ・名前付きの部品・操作の記録（設計メモ）

[competitive-gaps.md](competitive-gaps.md) の 2026-11-06 版の #3（人が画面を指して部品を選ぶ・光らせる）、#13（部品を名前を付けて共有する）、#10（操作の記録）をまとめて決める。3 つは「画面の部品をどう捕まえ、どこに置き、どう使い回すか」という同じ話の別の面なので、別々に作ると置き場所と形がずれる。

前提：

- AI が組みやすい仕様を最優先する（[ai-authoring.md](ai-authoring.md)）。人が使う機能を足しても、AI が書くものは増やさない。
- ブラウザの「指してもらう」「光らせる」は、AI が迷ったときに人に画面で指してもらう取り組みと共通にする。browser-adapter の `pick` / `highlight` を、Studio のピッカーも使う。
- デスクトップは UI Automation（UIA）。Windows 以外は考えない。

## 1. 画面から選ぶ（ピッカー）と光らせる

### 使う場面

- インスペクターの「対象」の枠の右上に 2 つのボタンを置く：**画面から選ぶ**、**光らせる**（今の画面で見つかるか試し、見つかればその部品を数秒枠で囲む）。
- 対象の欄がないノードには出さない。ブラウザかデスクトップかはノードの種類で決まる。

### 流れ（デスクトップ）

1. 「画面から選ぶ」を押すと Studio を最小化し、画面上部に小さな案内（「選びたい部品をクリック・Esc でやめる」）を出す。
2. マウスの下の部品を UIA の `ElementFromPoint` で取り、枠で囲んで追いかける。
3. クリックはアプリに渡さず（低レベルのマウスフックで止める）、その部品を選んだことにする。Esc でやめる。60 秒で時間切れ。
4. Studio を元に戻し、対象の欄に入れる。

選んだ部品から対象を組む順（なるべく壊れにくいものから）：

1. ウィンドウ：`process`（exe 名）。同じ exe のウィンドウが複数あるときだけ `title` を足す。タイトルは日付や番号を外した残り（`請求書_2026年11月.xlsx - Excel` → 「請求書」、`target::steady_title`）を含むで使い、それが別のウィンドウにも当たるときはタイトル全体を含むで、それでも当たるときは完全一致にする。
2. 部品：`id`（AutomationId）がウィンドウの中で一つに決まればそれだけ。
3. なければ `role` ＋ `name`。それでも複数なら `nth`。
4. 名前も ID もない部品（描画だけのアプリ）は、ウィンドウの左上からの位置（`point`）にし、「位置で指しています。画面の配置が変わると外れます」と出す。

返す形は Runtime の対象（`target`）そのもの。Studio は返ってきたものを欄に流し込むだけにし、組み立ての知恵は Rust 側に一か所だけ置く（MCP の AI からも同じものが使える）。

### ウィンドウと部品を分けるか（2026-11-08 決定）

「先にウィンドウを選び、次にその中の部品を選ぶ」二段階（UiPath の Use Application 型）も比べた。どのウィンドウを指したかは一回のクリックでも取り違えない。迷うのは「次にそのウィンドウを何で探すか」が見えないことで、これは選ぶ回数ではなく見せ方の問題なので、クリックは一回のままにした。

- 選んでいる間：オレンジの枠（ウィンドウ）の角に探し方の札（「Excel ・ タイトルに「請求書」を含む」）、青い枠（部品）の下に部品名の札。札の文言は Studio が `labels` で渡す（`target::describe_window`）。開いているウィンドウの一覧は Win32 だけで取り、UIA は待たない。画面の上の帯はやめ、「クリックで選ぶ ・ Esc でやめる」だけの小さな帯を画面の下に出し、マウスが近づくと上へ逃がす（最大化したアプリのタイトル・タブを隠さない）。
- 選んだあと：ノードの設定でウィンドウを部品と別の行にし、探し方を言葉の選択肢（どれでも／日付を外したタイトルを含む／タイトルを含む／タイトルだけ）から選ぶ。候補は picker の答えの `windowChoices`。同じ exe を別の探し方で使うノード・部品は「探し方をそろえる」でまとめて同じにする。
- ウィンドウそのものに働くノード（閉じる・状態を変える）は `scope: "window"` でウィンドウだけを選ぶ。
- 保存の形（`target.window`）は変えない。AI の書き方も今のまま。
- ブラウザはタブ・フレームを自動で扱っているので二段階にしない。

### 流れ（ブラウザ）

- browser-adapter の `pick` を呼ぶ。返る `target`（`role` / `name` / `exact` / `nth` など）はブラウザの対象の欄と同じ形。
- ページが開いていないと選べない。試し実行・ステップ実行の一時停止中なら、その開いているページで選ぶ。開いていなければ、そのノードより前の `browser.open` の URL を開いてから選ぶ（ログインが要るページは、一時停止中に選ぶよう案内する）。

### 入口（Rust）

- 新しい trait のメソッドは足さず、各アダプターの `inspect` に `action` を渡す（AI の「指してもらう」と同じ）。
  - `desktop`：`{ "action": "pick", "message"? , "timeoutMs"? }` → `{ "target", "rect", "text", "unique": bool, "how": "id" | "name" | "nth" | "point" }`、`{ "action": "highlight", "target", "ms"? }` → `{ "found": bool, "rect"? }`
  - `browser`：上の取り組みで足す `pick` / `highlight`
- Studio は Tauri のコマンド `pick_target` / `highlight_target`（`{ adapter, session?, ... }`）でこれを呼ぶ。

## 2. 名前付きの部品（パーツ）

### 置き場所と形

フロー（＝プロジェクトフォルダー）の `flow.json` に `parts` を足す。

```json
"parts": {
  "saveButton": {
    "label": "保存ボタン",
    "app": "desktop",
    "target": { "window": { "process": "billing.exe" }, "element": { "id": "btnSave" } }
  }
}
```

ノードは対象の代わりに名前を書く：

```json
{ "type": "desktop.click", "params": { "target": { "part": "saveButton" } } }
```

- キーは変数と同じく英数字（AI が書き間違えにくく、式の中でも崩れない）。人向けの名前は `label`。
- `app` は `browser` / `desktop`。ノードの種類と合わなければ検証エラー（直し方の `hint` 付き）。
- `{ "part": … }` と他の項目を混ぜない（上書きの書き方を作らない。1 つのことは 1 通り）。「3 行目のボタン」のように少しずつ違うものは、別の部品にする。
- 存在しない名前は検証エラー。
- Runtime はノードを動かす前に `{ "part" }` を中身に置き換える。アダプターは今のまま。実行記録には置き換えた後の対象も残す。

### 決めたこと・やらないこと

- **フローごと**に置く（UiPath のオブジェクトリポジトリがプロジェクト単位なのと同じ）。フローをまたいで共有する「部品集」は、サブフローで同じ画面を扱う例が増えてから。形は同じ `parts` をワークスペースに置くだけで済むようにしておく。
- 部品の写真（選んだときの切り抜き）は `flows/<フロー名>/parts/<name>.png` に置き、Studio が一覧と確認に使う。実行には使わない（画像で探すのは `image` の対象で、別物）。
- 画像で探す対象も部品にできる（種類「画像」）。ノードの「画面から切り取る」で画面を暗くして矩形をドラッグし、切り取った PNG を `templates/<キー>.png` に置いて、`target` に `image.path` を持つデスクトップの部品にする（保存形式は変えない）。一致率（`threshold`）・クリック位置（`offset`）・探す範囲（`window`／`region`）は部品の画面で直し、「撮り直し」で画像だけ差し替える。アダプターの inspect は `action: "snip"`（`{ target: { window }, png, width, height }`）。

### Studio

- 左のプロジェクトの棚に「部品」の段を足す：名前・写真・使っているノードの数。押すとインスペクターに部品の性質（名前・対象の欄・光らせる・選び直す）。
- ノードの対象の欄：「部品」を選ぶ欄（候補は同じアプリの部品）と、その場で書く欄を切り替える。その場で書いた対象は「部品にする」で名前を付けて移せる。同じ対象を書いたノードが他にもあれば、まとめて置き換えるか聞く。
- 画面が変わったときは部品を「選び直す」だけで、使っているノードすべてに効く。

### AI（MCP）

- `get_flow` に `parts` が入る。`edit_flow` の EditOp に `setPart` / `removePart` を足す。
- 同じ対象を 2 か所以上に書くときは部品にする、を `get_step_schema` の記述例と hint で勧める（必須にはしない）。

## 3. 操作の記録 → AI が整える

### 記録

- フロー図のドック（「ノード追加」の隣）に「記録」。押すと Studio を小さくし、画面の上に記録中の帯を出す（クリックで止める）。
- デスクトップ：低レベルのマウス・キーボードフックで、クリックした部品（1 と同じ組み立て）・入力欄の文字・押したキーを拾う。クリックとコマンドのキーはフックで止め、画面を読んでからアプリに渡す（押した後の画面ではなく押したものを捕まえる）。打った文字はキーからではなく、欄を離れたときの値を UIA で読む（IME の日本語も同じに扱える）。読めない欄は `desktop.type`（文字は空）にして人に埋めてもらう。
- ブラウザ：SpellSheet が開いたページだけ。browser-adapter に記録用の上書き（クリック・入力・選択を拾う）を足す。人がふだん使っているブラウザは記録しない（[competitive-gaps.md](competitive-gaps.md) #4 と同じ制約）。
- パスワード欄に打った文字は記録しない（`(パスワード)` とだけ残し、あとでシークレットを選ばせる）。

### 記録したあと

止めると「記録した操作」の一覧を出し、次のどちらかを選ぶ：

- **そのままノードにする**：1 操作 1 ノードで、選んでいる位置に足す。部品は同じものをまとめて `parts` に入れる。AI を使えない職場でもここまでで動く。
- **AI に整えてもらう**：記録（操作の列・部品・画面の写真）を AI のペインに渡し、「待ちを入れる・繰り返しにまとめる・入力を変数にする」などを頼む。AI の変更はいつもどおり確認待ちに入る。

記録の生データは `flows/<フロー名>/logs/recordings/` に置く（`work/` は実行のたびに空になるため。`logs/` の古い実行ログの削除は記録に触れない）。

## 作る順

1. デスクトップの `pick` / `highlight`（Rust、UIA）と Studio のボタン。ブラウザは上の取り組みの `pick` が入りしだいつなぐ。
2. `parts`（スキーマ・検証・Runtime の置き換え・EditOp・Studio の棚と欄・MCP）。
3. 記録（デスクトップ → ブラウザ）と「AI に整えてもらう」。

どれも Windows の実機で確かめる（UIA のフックと最小化・前面化は CI では試せない）。
