# Studio の画面の骨組みと決まり（設計メモ）

目的：Studio のボタンや表示を「空いている所」に置かない。画面全体を決まった骨組みで分け、どの機能も「何に効くか」で置き場所が一つに決まるようにする。今後の機能（実行履歴、スケジュール実行、プラグイン、通知など）も、この骨組みのどこに入るかを先に決めておく。

見た目の土台（ロゴに合わせた白地・濃紺文字、Material Design の高さ、角 2〜4px、虹色なし、Noto Sans JP）は `apps/studio/src/index.css` の冒頭にある。このメモは、その上で「何をどこに置くか」を決める。

## 骨組み

```
┌ サイドバー ────┬ タイトルバー ────────────────────────────────────────────────┐
│ ●保存先    ⇤ │ 名前 リビジョン▾ ✓検証  [フロー図|手順書|変数] ステップ実行 [▶実行] ─ □ ✕ │
│ Claude Code   ├────┬────────────────────────────────────────┬──────┤
├────────────┤ AI │ [目次]  作業面（フロー図）  [↑ ↓ まとめる… ✕] │ イン │
│ フロー       │ ペ │                                         │ スペ │
│  └ 開いている │ イ │  [＋ ノード追加 ● 記録 | ↶ ↷]（ドック）  │ クタ │
│ 確認待ち    2 │ ン ├ 下パネル：実行ログ | 検証結果 ──────── ✕ ┤ ー   │
│ シークレット   │    │                                         │      │
│ 設定          │    │                                         │      │
├────────────┴────┴────────────────────────────────────────┴──────┤
│ AI の動き                              実行の状態  ノード 3 / 12  JA EN  テーマ  v0.1.0 │
└ ステータスバー ───────────────────────────────────────────────────────┘
```

| 区画 | 役割 | 置くもの |
| --- | --- | --- |
| サイドバー（左端、上端まで、208px） | どこにあるか・どの仕事をするか | 上端にロゴと保存先（押すと設定）と隠すボタン、場所の行（フロー、その下に開いているフロー、確認待ち、シークレット）、下端に設定。一覧は置かない |
| タイトルバー | 今開いているものと、それへの操作 | フロー名・リビジョン（履歴を開く）・検証、表示の切替・ステップ実行・実行、ウィンドウ操作。ページの場所ではページ名。サイドバーを隠しているときは左端に表示ボタン |
| 確認待ちの一覧 | 確認待ちの場所で何を開くか | サイドバーと作業面の間に出る |
| 作業面 | 作業そのもの | フロー図／手順書、プロジェクトの棚（左に浮かぶ）、目次（その右）、選んだノードの操作、ドック、ズーム |
| ファイルのシート（作業面の右に浮かぶ） | フローのフォルダーのファイル | 設定ファイルのフォーム、テキスト、実行ログ。棚のファイルを押すと開き、Ctrl+S で保存 |
| 下パネル | 経過と結果の一覧 | 実行ログ、検証結果 |
| インスペクター（右） | 選んだものの性質 | ノードを選べばノードの要約（読むだけ）、何も選ばなければフロー |
| ノードの画面（作業面と右を覆う） | 一つのノードの設定 | ノードのダブルクリックか、インスペクターの「設定を開く」で開く。左「使える値」、中央「設定」、右「実行結果」。ノードの設定を変えるのはここだけ（`components/NodeEditor.tsx`） |
| AI ペイン（サイドバーの右隣） | どの場所からも使う相棒 | Claude Code との会話。サイドバーの最上段の「Claude Code」（Ctrl+J）で開閉する。チャットは左に置き、作業面とインスペクターの「選ぶ→性質を見る」の左右の流れを分断しない（Notion AI・Linear と同じ） |
| ステータスバー | 報告と見た目の切替 | 保存先、AI の動き、実行の状態、ノードの位置、言語、テーマ、バージョン |
| ダイアログ | 今の作業を止めて答えるもの | 履歴（記録・版）、コマンドパレット、AI からのログイン登録依頼 |

### 場所（サイドバー）

Linear・Notion と同じく、左は 1 本のサイドバーにまとめる。アイコンだけの列と一覧の列を二重に並べない。場所は「仕事の種類」ごとに一つで、文字とアイコン（lucide、16px、線幅 1.75）の行で示す。場所を切り替えると、サイドバーより右がすべて入れ替わる。

- **フロー**（一覧のページ）：すべてのフローの表。検索・並び順・タグで絞り込み、新規作成・ファイルから読み込む（主ボタンは右端の「新規作成」）、行のホバーで複製・削除。行を押すと開く。一覧はサイドバーに常駐させず、このページで管理する。
- **開いているフロー**（エディター）：サイドバーの「フロー」の下に名前の行が出る。作業面・インスペクター（名前と操作はタイトルバー）。作る・直す・試す。作業面は「フロー図・手順書・変数」の 3 つの見方を切り替える。「変数」はフローの変数すべての表（向き・名前・型・初期値・書き込むノード・読むノード・実行後の値）で、ノードを押すとフロー図でそのノードを開く。変数の編集はインスペクターのフロー表示で、ノードの設定の編集はノードの画面でする。
- **確認待ち**：確認待ちの一覧・作業面（AI の変更に印）・右に確認のパネル。パネルは判断の順に「1 変わること（前と後をフロー図と同じ文で）→ 2 外への影響 → 3 試しの結果 → 4 確かめてほしいこと（AI から）」と並べ、下端に判断（確認して公開／差し戻す／取り消す）と、押すと何が起きるかの一文を置く（[review-evidence.md](review-evidence.md)）。
- **シークレット**：登録済みのログイン情報と登録フォーム。
- **設定**（下端）：保存先、表示（言語・テーマ）、実行の許可、AI エージェント、バージョンと更新。仕事ではないので、仕事の場所から離して下端に置く。Windows 11・VS Code の設定と同じ形で、左に節の目次（読んでいる節に印、押すとその節へ）、右に節を幅いっぱいに並べる。節の中は 1 枚のシートに 1 設定 1 行で、左に名前と短い補足、右に入力欄をそろえる（`components/settingsLayout.tsx` の `SettingsGroup`・`SettingsRow`）。ボタンはシートの下端の右に置く。幅が狭いと目次を隠し、名前と入力欄を縦に並べる。

### 今後の機能の置き場所

先に決めておき、増えたときにボタンを散らばらせない。

| 機能 | 置き場所 |
| --- | --- |
| 実行履歴（過去の実行と証跡） | サイドバーの場所に「実行」を足す。実行の一覧はサイドバーと作業面の間、作業面がその実行のフロー図 |
| スケジュール実行・トリガー | 「実行」の場所の中のタブ。フロー側には、インスペクターのフロー表示に「スケジュール」の節を足す |
| 公開版（無人実行に使う版） | タイトルバーのリビジョンの隣に「公開版 n」を出し、履歴ダイアログの「版」から公開する |
| 前へ・次へ（開いたフローの行き来） | タイトルバーの左端 |
| 全体の検索（フロー・ノード・シークレットを横断） | サイドバーの保存先の下に検索の行。Ctrl+K はノードの追加のまま、検索は Ctrl+P |
| プラグイン（ノードの追加） | 設定に「プラグイン」の節。フローで使うノードはコマンドパレットに並ぶ |
| 通知 | 人を待つものはサイドバーの場所の数、終わった知らせはステータスバー |
| 新しい種類のノードの設定 | ノードの画面の「設定」の中（インスペクターには要約の 1 行が自動で出る）。専用ボタンは作らない |

新しい場所は `components/Sidebar.tsx` に 1 行足す。サイドバーには場所の行だけを置き、一覧はその場所のページに置く。新しい設定は `components/SettingsPage.tsx` に節を足す。

## 原則

### 1. 置き場所は「何に効くか」で決める

上の表のとおり、範囲が広いものほど外側（上・左）、狭いものほど内側に置く。ボタンの位置を見れば、押したときにどこまで変わるかがわかる。サイドバーの場所はどのフローを開いていても意味が変わらず、タイトルバーのボタンは必ず今開いているフローに効き、ノードのそばのボタンはそのノードにだけ効く。

ウィンドウは一度に一つのフローを開くので、タイトルバーがそのフローの見出しと操作を兼ねる。Linear・Notion・Claude のデスクトップ版と同じく、上端は「サイドバー（保存先）」と「開いているものと操作（タイトルバー）」に分け、見出しのための帯をもう一段重ねない。作業面は縦に 40px 広くなる。

### 2. インスペクターは「選んだものの性質」だけ

インスペクターには、選んだものが「何であるか・どう動くか」だけを出す。

- ノードを選んだとき：種類と文（見出し）、AI の変更と検証の指摘（そのノードのもの）、設定の要約（表示名と、値のある設定を「名前：値」で 1 行ずつ）と「設定を開く」、出力、つながり、値のある実行の設定。インスペクターでは編集しない。幅 420px では欄が細く、毎回触る設定と触らない設定が同じ段に並んで読めなくなるため、編集はノードの画面にまとめる（同じ設定を二か所で編集できるようにしない）。
- 何も選んでいないとき：フローそのもの。基本（名前・説明）、変数（入力・出力・内部）、実行の設定（既定のタイムアウト・エラー時）。
- 上端に「フロー › ノード」の道筋を出し、フロー名を押すとフローの表示に戻る。

ノードの画面は、インスペクターと同じ並び（基本・設定・出力・実行の設定・つながり）を幅いっぱいに出し、左に「使える値」（前のノードの結果・繰り返し中の行の列。押すと最後に触った欄に入る）、右に実行結果を置く。右上のボタンは二つで、強さは同じ（枠線）：

- **ノードの単体実行**：このノードだけを実行する。前のノードは実行しない。読む変数には前回の実行の値（なければ初期値）を使い（`lib/stepTest.ts`）、値のない変数があれば押せず、理由をツールチップに出す。実行の記録（`runs/`）には残さない。AI の `test_step` と同じ一ノードのフローで動かす（`shikigami_runtime::single`）。
- **ここまで実行**：先頭からこのノードまで実行し、このノードの直後で一時停止する。前のノードも実際に動く（メールの送信なども）ので、そう書いたツールチップを付ける。

性質ではないものは入れない。記録と版はフローの過去なので「履歴」（リビジョンから開く）、検証結果はフロー全体の一覧なので下パネル、「サブフローにまとめる」は操作なのでノードのそばに置く。

### 3. 操作は対象のそばに置く

選んだノードの並べ替え・まとめる・削除は、そのノードの見出しの右に出す。上下の中央にはフローの線が通り、見出しより下の行の横には変数のチップが並ぶので、見出しの横が空いている。ポインターはもうノードの上にあるので遠くへ動かさなくてよく、選んでいないときは出ないので押せない灰色のボタンも並ばない。

ノードを足す場所もそのそばで決める。フロー図の線にポインターを置くと線の上に「＋」が出て、押すとその線の先のノードの前に足す（分岐の見出しのある線では見出しの右）。中身が空の枠は、押すとその枠に足すパレットが開く。どこからも選べないときは、選んだノードの次、何も選んでいなければフローの最後に足す。

開くものは開く場所のそばに置く。目次ボタンは目次が開く作業面の左上の角に浮かべ、開いた目次の見出しに ✕ を置く。リビジョンは履歴、検証は下パネル、Claude Code は AI ペインが開くサイドバーの最上段。

### 4. 読む順に並べ、主ボタンで終える

帯の中は左から「どこにあるか → 何か → 状態はどうか → どう見るか → どうするか」の順に並べる。一番大事な操作（主ボタン）は帯の右端に置き、名前の長さが変わっても位置が動かないようにする。タイトルバーのフローの操作は「実行」、ページの見出し行は「新しく登録」で終わる。その右のウィンドウ操作は、どの場所でも同じ位置にある。

### 5. 一つの面に塗りつぶしのボタンは一つ

| 強さ | 見た目 | 例 |
| --- | --- | --- |
| 主 | 濃紺（ink）の塗りつぶし | タイトルバーの「実行」、ドックの「ノード追加」、AI の変更の「確認して公開」 |
| 副 | 枠線 | 「ステップ実行」 |
| 補助 | 枠なし、ホバーで地色 | 目次、元に戻す、↑ ↓、まとめる… |
| 危険 | 朱の文字または枠 | 「停止」「変更を取り消す」、✕ はホバーで朱 |

### 6. 一つの事実は一か所で示す

同じ数や状態を二か所に出さない。

- 確認待ちの件数：サイドバーの「確認待ち」の数だけ。
- AI からのログイン登録の依頼：サイドバーの「シークレット」の数だけ。
- 検証の結果：タイトルバーの「検証OK / エラー n 件」。押すと下パネルの検証結果が開く。
- フローの名前：タイトルバーだけ。インスペクターの見出しは「フロー」「フロー › ノード名」とし、名前を繰り返さない。
- 保存先：サイドバーの上端だけ（フォルダー名。全体のパスはツールチップと設定）。
- 更新があること：サイドバーの「設定」の点と、ステータスバーのバージョン表示。

### 7. バッジは人を待つものだけを数える

- 朱の数字：人の確認を待っている（確認待ち、記録の未確認）
- 橙の数字：人の入力を待っている（ログインの登録依頼）
- 青の点：見ておくとよいが、急がない（更新）
- 灰の数字：知らせるだけ（検証結果の件数）

登録済みのシークレットの数のような在庫の数には付けない。

### 8. ステータスバーは報告だけ

左に「AI と実行が何をしているか」、右端に「ノードの位置 → 言語・テーマ → バージョン」。バージョンを押すと設定が開く（変えるのは設定でする）。保存先は「どこにあるか」なので、サイドバーの上端に置く。言語とテーマはよく切り替えるので、設定と同じものをここにも置く。

### 9. 幅が足りないときは、外側から譲る

作業面（フロー図）を最後まで残し、幅 480px を下回らせない。足りなくなったら、外側の部品から次の順に譲る（`apps/studio/src/lib/fit.ts`）。

1. サイドバーを隠す。タイトルバーの左端の表示ボタン（Ctrl+B）で、サイドバーが作業面の上に一時的に重なって開き、場所を選ぶと閉じる（Linear・Notion の狭い画面と同じ）。手で隠したサイドバーは、表示ボタンで元の列に戻る。
2. 確認待ちの一覧を細い帯（44px）にたたむ。帯の » で同じように重ねて開く。
3. AI ペインを 380px から 320px に細くする。
4. それでも足りなければ、AI ペインがインスペクターの場所を借りる。AI ペインを閉じればインスペクターが戻る。AI ペインを閉じている間は、インスペクターは必ず出す。

何も開いていないときはインスペクターの列そのものを出さない。ウィンドウの最小幅（960px）でも、この順で作業面 480px が残る。

サイドバー・確認待ちの一覧・インスペクター・AI ペイン・下パネルは、作業面側の縁のつまみをドラッグして大きさを変えられる（VS Code・Linear と同じ）。つまみは境界線の上に重なる細い帯で、ホバーとドラッグ中だけ青い線を出す。ダブルクリックで既定の大きさに戻し、矢印キーでも動かせる。変えた大きさは覚えておき、上の譲り方はその大きさで計算する。ドラッグで作業面を 480px より狭くはできない。

タイトルバーは狭くなると「リビジョン」「検証OK」「ステップ実行」の文字を記号に替える。フロー名と「実行」は文字のまま残す。部品の幅は決まった値にし、中身の長さで列が広がらないようにする。

### 10. 高さ（影）は意味で決める

| 高さ | 影 | 使う所 |
| --- | --- | --- |
| 1dp | `shadow-sheet` | 机に置いた紙：設定やシークレットの節、選ばれた切替 |
| 2dp | `shadow-node` | フロー図のノード |
| 4dp | `shadow-raised` | 作業面に浮く道具：ドック、目次、ノードの操作、ズーム |
| 8dp | `shadow-lifted` | 持ち上げたもの：選んだノード、メニュー、ポップアップ |
| 24dp | `shadow-dialog` | ダイアログ、コマンドパレット、画像の拡大 |

サイドバーと確認待ちの一覧は机（paper）、作業面は一段低い机（desk）、インスペクター・タイトルバー・ペインは紙（sheet）。

### 11. 色は役割、角は 2〜4px

- 青（brand）＝AI、橙＝実行中・変更あり・人の入力待ち、朱＝エラー・危険・人の確認待ち、緑＝成功・検証OK。ノードや変数の種類の色は、ノードの見出しとソケットだけに使う。
- ロゴの 4 色は、フローのフォルダーのファイルの役割にも使う：水色＝入力（input/）、青＝設定（config/）、緑＝テンプレート（templates/）、橙＝出力（output/）。棚の印、ノードのファイルの項目の左の線と地の色だけに使い、飾りには使わない。
- 実行の跡：実行が通ったノードの枠と線を、同じ役割の色（緑＝通った、朱＝止まったノードへの線、橙＝実行中）で塗る。終わったあとも残し、フローを編集したとき・次の実行・別のフローを開いたときに消える。手で消すのは下パネルの実行ログの「図の色を消す」（右クリックにも同じもの）。
- 虹色はロゴマークだけ。
- 角はすべて 2〜4px。丸は状態の点とブレークポイントだけ。
- 薄い色で目を疲れさせない。補足の文字は白地で 4.5:1 以上（slate-400 以上、本文の補足は slate-500）、枠線は slate-200。灰色は `index.css` の slate を一段濃くしてあるので、新しく別の灰色を足さない。使っていないものを薄くするときも opacity は 75% まで。
- ダークテーマの地はスレートグレー（青みを抑えた灰色）。紺や青の地にはしない。青は AI などの意味のある印だけ。

### 12. 文字か記号か、大きさ

- 業務の言葉で呼ぶ操作は文字にする（「実行」「ノード追加」「シークレット」「Claude Code」）。説明調・話し言葉にしない。
- 形でわかるものだけ記号にする（↑ ↓ ✕ ↶ ↷、ウィンドウ操作）。サイドバーの場所は文字に小さなアイコンを添える。アイコンは lucide にそろえ、手描きの SVG を足さない。画面の中で別の意味に使っているアイコンと似た形は選ばない（設定に歯車を使うとテーマ切替の太陽と見分けにくいので、スライダーの形にする）。記号だけのボタンには `title` を付け、ショートカットを書き添える。
- タイトルバー・インスペクターの見出し・確認の見出しはどれも 40px にそろえ、下の線を一本につなげる。帯の中の操作は 24〜32px、ステータスバー（28px）の中は 20px。

### 13. フローの線

線はノードの上下の中央から出入りし、曲がり角を越えて先へ伸ばさない（分岐の横線より下へはみ出さない）。線の端を受ける点（ハンドル）は手でつなぐものではないので描かない。

### 14. ノードを探す（パレット）

ノードはパレット（Ctrl+K・ドックの「ノード追加」・線の「＋」・空の枠と最後のノードの下の「＋ ノード追加」・右クリックの「ここにノードを追加」）一つで選ぶ。入口が違っても中身は同じにする（`components/CommandPalette.tsx`、`lib/palette.ts`、アイコンは `lib/nodeIcons.ts`）。

- 画面の真ん中に暗幕を掛けて出さない。押したもの（「＋」・枠・ドック。Ctrl+K なら選んだノード）のすぐ下か上に浮かべ、フロー図と足す場所を隠さない（8dp）。外を押すか Esc で閉じる。
- 開くと上に「よく使う」：最近足したノードと、よく使うノード（合わせて 6 件）。その下に分類。分類を押すとその場で中に入り、左上の ‹ か ← ・Esc で戻る。
- 分類は「何を操作するか」で分ける。見出しは「操作するもの（ブラウザ・Excel・Word・Outlook・ファイル・デスクトップアプリ・Web API・ダイアログ・システム）→ 流れ（制御・変数・待機・ログ）→ 値の加工（文字・数値・日付・表・リスト）」。Office はアプリごとに分ける（人は「Excel」で探す）。流れの「制御」の次に「サブフロー」：入力か出力を持つフロー（開いているもの以外）を名前でノードとして並べ、選ぶとその呼び出しを足す。プラグインの分類は最後。
- 各行はアイコン（分類の色の地）・名前・何をするかの一文（`locales/stepHelp.*.ts`、人向けの言葉。レジストリの説明は AI 向けなので出さない）。同じ名前（「クリック」）が別の分類にあるので、「よく使う」と検索では行の右に分類を出す。
- 検索は名前・別の呼び方（エクセル、ループ、待つ…）・説明を見て、名前に合うものを上に並べる。カタカナ／ひらがな、全角／半角は区別しない。IME で変換する前のかな（まつ、よむ）でも見つかる。
- 下端に「追加する場所」を出す（「メッセージ表示」の次、など）。どこに入るかを押す前に確かめられる。
- キー：↑↓ 選ぶ、Enter 追加（分類なら中へ）、→ 分類の中へ、← 戻る、Esc 閉じる。

### 15. 右クリック

ブラウザの右クリックメニュー（戻る・最新の情報に更新・印刷・開発者ツールで調査する）は出さない。デスクトップのアプリとして意味がないため。右クリックは「そのものに効く操作」を、そのものの上で開く近道にする（`lib/contextMenu.ts`、`components/menus.ts`）。

- メニューに入れるのは、そばのボタン・インスペクター・キーにすでにある操作だけ。同じ言葉とショートカットを書き添え、メニューにしかない操作は作らない。
- 開く前に右クリックしたものを選ぶ（ノード・空きの枠）。何に効くかがインスペクターでも見える。
- 置き場所ごとの中身：

| 右クリックしたもの | メニュー |
| --- | --- |
| ノード（フロー図・手順書） | サブフローを開く・中を表示／たたむ（呼び出しのとき）、上へ・下へ、無効にする、ブレークポイント、Claude Code に聞く、ID をコピー、削除 |
| サブフローの中のノード（読むだけ） | ブレークポイント、ID をコピー |
| 空きの枠 | ここにノードを追加 |
| フロー図の地 | ノード追加、記録、元に戻す・やり直す、全体を表示、図の色を消す・ブレークポイントをすべて外す（あるときだけ。実行ログの上にも同じボタン）、目次（サブフローの中では「元のフローに戻る」） |
| 変数（ノードのチップ・変数の表） | 名前をコピー、変数の設定、書き込むノードへ（表）、変数を削除 |
| フローの一覧の行 | 開く、複製、ID をコピー、削除（もう一度押して確定） |
| プロジェクトのファイル | 開く、アプリで開く、エクスプローラーで表示、パスをコピー、名前を変更、削除 |
| 入力欄 | 切り取り・コピー・貼り付け・すべて選択 |
| 選んだ文字 | コピー |
| それ以外 | 何も出さない |

- 見た目は持ち上げたもの（8dp、`shadow-lifted`）、アイコンは lucide、危険な操作は朱で最後に置く。↑ ↓ Enter Esc で操作できる。
- 開発版だけ、Shift を押しながら右クリックするとブラウザのメニュー（「開発者ツールで調査する」）が出る。F12・Ctrl+Shift+I もそのまま使える。

### 16. 値の加工と式の入力

現場の人に式を書かせない。フローに残すのは今までどおり「変数への代入」の `expression`（AI が書くのと同じ一つの書き方、[ai-authoring.md](ai-authoring.md)）で、Studio はその見せ方と入れ方を変える（`lib/transforms.ts`、`components/TransformForm.tsx`、`components/ExpressionField.tsx`）。

- **加工のフォーム**：式がよく使う形（`sum(map(rows, r => num(r.金額)))`、`trim(text)`、`filter(rows, r => num(r.金額) >= limit)` など 27 種）なら、インスペクターでは「加工：表の列を集計／集計：合計／表：rows／列：金額」のフォームで出す。変数はドロップダウン（前回の実行の値つき）、表の列は前回の実行の値から候補を出す。フォームは式を書き直すだけ。AI が書いた式も同じ形ならフォームで出る。
- フロー図・手順書の文と見出しもフォームと同じ言葉にする（「total に rows の「金額」の合計を入れる」、見出し「表の列を集計」）。
- パレットの「文字・数値・日付・表・リスト」は、このフォームの加工を並べる。追加すると既定の値で式が入り、フォームで変数を選び直す。
- 形に合わない式、条件（`condition`）・繰り返しの対象（`items`）などの式の欄は、式の入力欄で支える：
  - 変数は型の色の帯で示し、文字（緑）や数と見分けられるようにする。フローにない名前は朱の波線。
  - 入力中に変数・表の列（`r.` の後）・関数を候補に出す（関数は日本語の名前と説明、かなでも探せる。Ctrl+Space でも開く）。
  - カーソルのある関数の引数と説明を欄の上に出す（`locales/functionHelp.*`。Core の関数一覧は AI 向けなので出さない）。
  - 欄の下に、前回の実行の値で Core が計算した結果を出す（`eval_expression`）。値がまだなければ「実行すると…」、書き間違いは実行エラーと同じ言い換えで出す。大きい値は先頭だけ記録されるので、その場合は「一部で計算」と書き添える。
- 新しい加工を足すときは `TRANSFORMS` にテンプレートを足し、`locales/transforms.{ja,en}.ts` に名前・説明・文・項目名を書く。テンプレートは AI が書く普通の形にする（Studio のための書き方を作らない）。

### 17. ファイルはドラッグで渡す

ファイルの名前を打たせない。プロジェクトのファイル（プロジェクトの棚、ノードの画面の「このフローのファイル」）とエクスプローラーのファイルは、置いた先で意味が決まる（`components/FileDrag.tsx`、`lib/fileDrop.ts`）。

- ファイルの設定欄：そのファイルのパス（フローのフォルダーからの相対パス）が入る。フォルダーの外のファイルは棚に取り込んでから入れる。フォルダーの設定欄にはファイルのあるフォルダー。
- フロー図：そのファイルを読むノードを作る（ノードの上なら直後、空のブロックならその中、何もない所なら最後）。読むノードのない種類は取り込むだけ。
- プロジェクトの棚：エクスプローラーのファイルを、その棚（または名前から振り分けて）に取り込む。
- ドラッグ中は受け取れる欄を点線で囲み、ポインターの横に「ここに入れる」「このファイルを読むノードを作る」と出す。Studio の中のドラッグはポインターで追う（Windows では、エクスプローラーからのドロップを受けている間は HTML のドラッグ＆ドロップがページに届かない）。

## 新しいボタンや画面を足すときの手順

1. 何に効くかで区画を決める（骨組みの表、原則 1）。仕事の種類が新しいなら場所（サイドバー）、設定なら設定の節、選んだものの性質ならインスペクター。
2. 「今後の機能の置き場所」に載っていれば、それに従う。
3. 区画の中では読む順（原則 4）で位置を決める。
4. 強さを決める（原則 5）。その面にもう主ボタンがあれば、副か補助にする。
5. 同じ事実をもう出している所がないか確かめる（原則 6）。数を出すなら人を待つものか確かめる（原則 7）。
6. 文字か記号か、`title` とショートカット、日英の文言（`locales/{ja,en}.ts`）を用意する。
