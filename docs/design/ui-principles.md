# Studio の画面の決まり（設計メモ）

目的：Studio のボタンや表示を「なんとなく空いている所」に置かない。どこに置くか、どう見せるかを、毎回同じ理由で決められるようにする。新しいボタンを足すときも、このメモの順に考えれば置き場所と見た目が一つに決まる。

見た目の土台（ロゴに合わせた白地・濃紺文字、Material Design の高さ、角 2〜4px、虹色なし）は [studio-ai-pane.md](studio-ai-pane.md) などの既存メモと `apps/studio/src/index.css` の冒頭にある。このメモは、その上で「何をどこに置くか」を決める。

## 原則

### 1. 置き場所は「何に効くか」（範囲）で決める

画面は上から下へ、外から内へ、範囲が狭くなるように並べる。ボタンは、それが効く範囲の帯に置く。

| 範囲 | 置き場所 | 例 |
| --- | --- | --- |
| Studio 全体・ワークスペース全体 | タイトルバー | シナリオ / 確認待ち、シークレット、Claude Code、ウィンドウ操作 |
| 開いているシナリオ | シナリオバー（フロー図の真上） | 目次、名前・リビジョン、検証、フロー図 / 手順書、ステップ実行、実行 |
| フロー図全体の編集 | フロー図の下のドック | ステップ追加、元に戻す、やり直し |
| 選んだ手順 | その手順のすぐ上 | ↑ ↓（並べ替え）、✕（削除）、AI の変更を残す / 取り消す |
| 選んだもの・シナリオの詳細 | 右のパネル | 設定、変数、検証結果、記録、版 |
| 状態の報告とこの PC の好み | ステータスバー | 保存先、AI の動き、実行の状態、手順の位置、言語、テーマ、バージョン |

理由：ボタンの位置を見れば、押したときにどこまで変わるかがわかる。タイトルバーのボタンはシナリオを切り替えても意味が変わらず、シナリオバーのボタンは必ず今開いているシナリオに効く。

### 2. 操作は対象のそばに置く（近さ・Fitts の法則）

選んだ手順の並べ替えと削除は、その手順の右上に出す。ポインターはもう手順の上にあるので、画面の端まで動かさなくてよい。手順を選んでいないときは出さないので、押せない灰色のボタンが並ぶこともない。

開くものは、開く場所の真上に置く。目次ボタンは目次が開く位置（フロー図の左上）の真上、Claude Code ボタンは AI ペインが開く右端の真上にある。

### 3. 読む順に並べ、主ボタンで終える

日本語も英語も左から右へ読むので、帯の中は「何か → 状態はどうか → どう見るか → どうするか」の順に並べる。シナリオバーなら「目次・名前・リビジョン・検証 → フロー図 / 手順書 → ステップ実行 → 実行」。

一番大事な操作（主ボタン）は帯の右端に置く。名前の長さが変わっても位置が動かないので、目と手が覚えられる（Material のダイアログで確定ボタンが右端にあるのと同じ考え方）。

### 4. 一つの面に塗りつぶしのボタンは一つ

ボタンの強さは 4 段階に固定する。

| 強さ | 見た目 | 使う所 |
| --- | --- | --- |
| 主 | 濃紺（ink）の塗りつぶし | その面で一番よく押す操作。シナリオバーの「実行」、ドックの「ステップ追加」、AI の変更の「残す」 |
| 副 | 枠線 | 主と並ぶもう一つの選択肢。「ステップ実行」 |
| 補助 | 枠なし、ホバーで地色 | それ以外。目次、元に戻す、↑ ↓ |
| 危険 | 朱の文字または枠 | 消す・止める・取り消す。「停止」「変更を取り消す」、✕ はホバーで朱 |

塗りつぶしが二つあると、どちらを押すべきか迷う。だから一つの面（帯・ドック・ダイアログ・手順の上の操作）に主ボタンは一つだけにする。

### 5. 一つの事実は一か所で示す

同じ数や状態を二か所に出さない。二か所にあると、どちらを見ればよいか迷い、片方だけ古くなる。

- 確認待ちの件数は、タイトルバーの「確認待ち」タブのバッジだけ。
- AI からのログイン登録の依頼は、「シークレット」ボタンのバッジだけ。
- 検証の結果は、シナリオバーの「検証OK / エラー n 件」。押すと右のパネルの検証結果が開く。

### 6. バッジは「人を待っているもの」だけを数える

バッジ（色の付いた数字）は、人が何かしないと進まないものだけに付ける。登録済みのシークレットの数のような、ただの在庫の数には付けない。

- 朱：人の確認を待っている（確認待ち、記録の未確認）
- 橙：人の入力を待っている（ログインの登録依頼）
- 灰：知らせるだけ（検証結果の件数）

### 7. ステータスバーは報告だけ

ステータスバーは、今の状態を知らせる場所で、人に何かを求める場所ではない。左から「どこに保存しているか → AI と実行が何をしているか」、右端に「手順の位置 → この PC の好み（言語・テーマ）→ バージョン」。確認や入力を求めるものは、それに答えるボタンの方にバッジを付ける（原則 5・6）。

### 8. 高さ（影）は意味で決める

`index.css` の Material Design の高さを使い、任意の影は使わない。

| 高さ | 影 | 何に使うか |
| --- | --- | --- |
| 1dp | `shadow-sheet` | 机に置いた紙：パネル、カード、選ばれたタブ |
| 2dp | `shadow-node` | フロー図の手順 |
| 4dp | `shadow-raised` | フロー図の上に浮く道具：ドック、目次、手順の上の操作、ズーム |
| 8dp | `shadow-lifted` | 持ち上げたもの：選んだ手順、メニュー、ポップアップ、AI ペイン |
| 24dp | `shadow-dialog` | ダイアログ、コマンドパレット、画像の拡大 |

### 9. 色は役割、角は 2〜4px

- 青（brand）＝AI、橙＝実行中・変更あり、朱＝エラー・危険・人を待つ、緑＝成功・検証OK。手順や変数の種類の色は意味のある所（手順の頭、ソケット）だけに使う。
- 虹色のグラデーションはロゴマークだけ。
- 角はすべて 2〜4px（`rounded-[2px]`〜`rounded-[4px]`）。丸い形は状態の点（●）とブレークポイントだけ。
- 書体は Noto Sans JP（同梱）。明朝体・セリフ体は使わない。

### 10. 文字か記号か

- 業務の言葉で呼ぶ操作は文字で書く：「実行」「ステップ追加」「シークレット」「Claude Code」。説明調・話し言葉にしない（「〜と話す」「〜してもらう」は使わない）。
- 誰でも形でわかるものだけ記号にする：↑ ↓ ✕ ↶ ↷、ウィンドウ操作。記号だけのボタンには必ず `title` を付け、ショートカットがあれば `（Ctrl+Z）` のように書き添える。

### 11. 大きさをそろえる

- 帯（タイトルバー 40px、シナリオバー 40px、右パネルのタブ 40px）の中の操作は高さ 28〜32px。シナリオバーと右パネルのタブは同じ高さにして、下の線を一本につなげる。
- ドックと手順の上の操作は 24〜32px、ステータスバー（28px）の中は 20px。

## 画面の地図

```
┌ タイトルバー（全体）──────────────────────────────────────────┐
│ ● [シナリオ|確認待ち n]                    シークレット n  Claude Code  ─ □ ✕ │
├ 一覧 ──┬ シナリオバー（開いているシナリオ）──────────────┬ 右パネル ───┤
│        │ 目次  名前 リビジョン ✓検証   [フロー図|手順書] ステップ実行 [▶実行] │ 設定 変数 検証結果 記録 版 │
│        ├──────────────────────────────────────┤             │
│        │ ┌目次┐            [↑ ↓ | ✕]                │             │
│        │ └──┘            ┌選んだ手順┐                │             │
│        │                  └─────┘                │             │
│        │ ＋－□       [＋ ステップ追加 Ctrl+K | ↶ ↷]           │             │
├────┴──────────────────────────────────────┴─────────┤
│ 保存先  AI の動き                      実行の状態  手順 3 / 12  JA EN  テーマ  v0.1.0 │
└ ステータスバー（報告と好み）──────────────────────────────────┘
```

### 右パネルのタブの順

「設定 → 変数 → 検証結果 → 記録 → 版」。左から、手に取っている手順（設定）、シナリオの今の中身（変数・検証結果）、シナリオの過去（記録・版）の順で、範囲と時間が手前から奥へ進む。確認台にいるときだけ、先頭に「確認」が付く。

手順を選ぶと「設定」、AI の新しい変更が来ると「記録」、シナリオバーの検証を押すと「検証結果」に切り替わる。

## 新しいボタンを足すときの手順

1. 何に効くか（原則 1）で帯を決める。どの帯にも当てはまらないなら、まずコマンドパレット（Ctrl+K）に入れて、使われ方を見てから考える。
2. 帯の中では読む順（原則 3）で位置を決める。
3. 強さ（原則 4）を決める。その面にもう主ボタンがあるなら、副か補助にする。
4. 同じ事実をもう出している所がないか確かめる（原則 5）。
5. 数を出すなら、人を待っているものか確かめる（原則 6）。
6. 文字か記号か（原則 10）、`title` とショートカット、日英両方の文言（`locales/{ja,en}.ts`）を用意する。
