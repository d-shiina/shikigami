# Studio の画面の骨組みと決まり（設計メモ）

目的：Studio のボタンや表示を「空いている所」に置かない。画面全体を決まった骨組みで分け、どの機能も「何に効くか」で置き場所が一つに決まるようにする。今後の機能（実行履歴、スケジュール実行、プラグイン、通知など）も、この骨組みのどこに入るかを先に決めておく。

見た目の土台（Linear 風：中立の灰色・1px の枠線・控えめな影・角 4〜8px、色は状態と選択だけ、虹色なし、Noto Sans JP）は `apps/studio/src/index.css` の冒頭にある。このメモは、その上で「何をどこに置くか」を決める。

## 骨組み

```

│ ◐ SpellSheet ▾     [🔍 フロー・場所・操作を検索  Ctrl P] [✦ AI チャット Ctrl J]    — □ ✕ │
├ サイドバー ────┬ タイトルバー ──────────────────────────────────────┐ ┌ AI ──┐
│ 📁保存先    ⇤ │ フロー / 名前 ⟲履歴 ◌未公開 ✓検証 実行の状態 [フロー図|…] [▶実行] │ │ ペイ │
├────────────├────────────────────────────────┬──────────┤ │ ン   │
│ フロー       │ [目次]  作業面（フロー図）           │ インスペ │ │      │
│ 確認待ち    2 │                                 │ クター   │ │（作業 │
│ 自動実行      │  [＋ ノード追加 ● 記録 | ↶ ↷]（ドック） │ ノード3/12│ │ 面と別│
│ シークレット   ├ 下パネル：実行ログ | 検証結果 ─── ✕ ┤          │ │ の浮い│

│  📌 請求書…   │                                 │          │ │      │
```

部品は「窓全体のもの」と「開いているものに属するもの」に分ける。窓全体のもの（アプリの名前とメニュー・全体の検索・AI・ウィンドウ操作・場所の並び）は窓の灰色の地に直に置き、開いているものに属するもの（名前・状態・操作・選んだノードの位置）は作業面のパネルの中に置く。AI はフローが無くても使う（新しいフローを作る）ので、作業面の枠の中に入れず、別の浮いたパネルにする。

| 区画 | 役割 | 置くもの |
| --- | --- | --- |
| 窓の帯（上端、40px、窓の地） | このアプリと、窓全体の操作 | 左に「SpellSheet Studio ▾」（マークとアプリ名 `t.appName`、製品名を黒・画面の名前を灰色で。メニューにテーマ・表示言語・設定（Ctrl+,）・バージョン、更新があれば青い点と「更新があります」）。まん中に全体の検索（Ctrl+P）と、そのすぐ右に「AI チャット」（Ctrl+J）。右端にウィンドウ操作。残りは窓をつかんで動かす場所。Windows のアプリが左上に名前を出し、VS Code がコマンドセンターの隣に Copilot を置くのと同じ |

| ファイルのシート（作業面の右に浮かぶ） | フローのフォルダーのファイル | 設定ファイルのフォーム、テキスト、実行ログ。棚のファイルを押すと開き、Ctrl+S で保存 |
| 下パネル | 経過と結果の一覧 | 実行ログ、検証結果 |
| インスペクター（右） | 選んだものの性質 | ノードを選べばそのノードの設定（ここで編集する）と実行結果。**ノードか部品を選んだときだけ開き**、選びを外す（何もないところを押す・Esc・見出しの ×）と閉じて作業面に幅を返す。フローの設定（名前・説明・変数・実行の設定）は、タイトルバー右端の「右の欄」ボタンか開始・終了の札を押して開き、閉じるまで出したままにする（覚えておく）。「変数」の見方では出さない（表でそのまま直せるので）。見出しの右端に選んだノードの位置（ノード 3 / 12） |
| ノードの画面（作業面と右を覆う） | 一つのノードを広げて見る | インスペクターの「広げる」で開く。左「使える値」、中央「設定」、右「実行結果」。大きな表の結果や長い式を見るときだけ使う（`components/NodeEditor.tsx`） |
| AI ペイン（右端、作業面と別の浮いたパネル） | どの場所からも使う相棒 | 設定の「使う AI」で選んだ AI（Claude Code・Codex・Gemini CLI・GitHub Copilot）との会話。窓の帯のまん中、検索のすぐ右の「AI チャット」（Ctrl+J）で開閉し、右端に開く。検索に打った言葉は「AI に頼む」でそのまま AI チャットに書ける。フローが無くても使うので作業面の枠には入れない。AI が作業中のときは、ボタンの中に何をしているかを出す（ペインを閉じていても、どの場所からも見える）。AI は場所ではなく今開いているものを手伝う道具なので、サイドバー（場所の並び）には置かない。項目名は使う AI によらず同じにし、どの AI かはペインの見出しに出す。インスペクターのさらに右に置き、作業面→インスペクターの「選ぶ→性質を見る」の左右の流れを分断しない（VS Code の Copilot と同じ）。右端の取っ手で引き出す形は、VS Code・Notion・Linear のどれも採っておらず、ボタンと開く場所を近づけるだけならまん中の検索の隣で足りるので採らない（2026-11-08） |
| ダイアログ | 今の作業を止めて答えるもの | 履歴（記録・版）、コマンドパレット、AI からのログイン登録依頼 |

### 場所（サイドバー）

Linear・Notion と同じく、左は 1 本のサイドバーにまとめる。アイコンだけの列と一覧の列を二重に並べない。場所は「仕事の種類」ごとに一つで、文字とアイコン（lucide、16px、線幅 1.75）の行で示す。場所を切り替えると、サイドバーより右がすべて入れ替わる。

- **フロー**（一覧のページ）：すべてのフローの表（共通のデータテーブル、[data-table.md](data-table.md)）。列は名前・説明・公開・自動実行・タグ・ノード・更新。検索と「公開」「自動実行」「タグ」の絞り込み、「表示」、主ボタンは右端の「新規作成」（▾ にファイルから読み込む・AI の答えを貼り付け）。行を押すと開き、右端の「…」と右クリックで複製・書き出し・削除。一覧はサイドバーに常駐させず、このページで管理する。
- **開いているフロー**（エディター）：サイドバーの「最近のフロー」に名前の行があり、タイトルバーの道筋「フロー / 名前」の「フロー」で一覧に戻る。作業面・インスペクター（名前と操作はタイトルバー）。作る・直す・試す。作業面は「フロー図・手順書・変数」の 3 つの見方を切り替える。「変数」はフローの変数すべての表（向き・名前・型・初期値・書き込むノード・読むノード・実行後の値）で、ノードを押すとフロー図でそのノードを開く。初期値・型・向きは表のセルでそのまま直す（表計算と同じく、ホバーで枠、Enter で確定、Esc で戻す）。機密にする・削除は右クリック、変数の追加は表の下の行。右の欄は出さない。ノードの設定の編集は右の欄とノードの画面でする。
- **確認待ち**：確認待ちの一覧と、作業面いっぱいの「紙のレポート」（手順書と同じ机の上の白い紙）。判断の順に「AI からの説明 → 3 つの数字 → こうなれば正しい → あなたにしか分からないこと → 外への影響 → 変わったところ（前と後を左右に）」と並べ、下端に判断（確認して公開／差し戻す／取り消す）と、押すと何が起きるかの一文を置く。フロー図・手順書・変数には表示切り替えで移り、そこでも下に判断の帯が残る（[review-evidence.md](review-evidence.md)）。
- **シークレット**：登録済みのログイン情報と登録フォーム。
- **最近のフロー**：手を付けているフローへの近道（Linear のお気に入り・Notion の「最近」と同じ）。固定したフロー（行のピン）が先頭、そのあとに最近開いた順で、合わせて 6 件まで。押すとそのフローに切り替わる。実行中は橙、AI が作業中は青の点が付く。窓は一度に一つのフローを開くので、開いているフローを全部並べるタブやツリーにはしない（全部の一覧はフローのページ）。

- **設定**（下端）：保存先、表示（言語・テーマ）、実行の許可、AI エージェント、バージョンと更新。仕事ではないので、仕事の場所から離して下端に置く。Windows 11・VS Code の設定と同じ形で、左に節の目次（読んでいる節に印、押すとその節へ）、右に節を幅いっぱいに並べる。節の中は 1 枚のシートに 1 設定 1 行で、左に名前と短い補足、右に入力欄をそろえる（`components/settingsLayout.tsx` の `SettingsGroup`・`SettingsRow`）。ボタンはシートの下端の右に置く。幅が狭いと目次を隠し、名前と入力欄を縦に並べる。

## 原則

### 1. 置き場所は「何に効くか」で決める

上の表のとおり、範囲が広いものほど外側（上・左）、狭いものほど内側に置く。ボタンの位置を見れば、押したときにどこまで変わるかがわかる。サイドバーの場所はどのフローを開いていても意味が変わらず、タイトルバーのボタンは必ず今開いているフローに効き、ノードのそばのボタンはそのノードにだけ効く。

ウィンドウは一度に一つのフローを開くので、タイトルバーがそのフローの見出しと操作を兼ねる。その上の窓の帯は窓全体のもの（名前・検索・AI・ウィンドウ操作）だけを置き、開いているものの名前と操作はタイトルバーに置く。Windows では窓の右上にウィンドウ操作の帯がどうしても要るので、その帯に名前・検索・AI を載せ、ステータスバーはやめる（2026-11-08。Linear 型の 1 段も比べたが、見出しの右端にウィンドウ操作と AI が入ってフロー名が切れるので採らなかった）。

### 2. インスペクターは「選んだものの性質」だけ

インスペクターには、選んだものが「何であるか・どう動くか」だけを出す。

- ノードを選んだとき：種類（右上に「広げる」）、表示名（その場で直す）、一行の説明、AI の変更と検証の指摘（そのノードのもの）、設定（ここで編集する）、実行結果（「ここまで実行」「ノードの単体実行」のボタンと、前の実行・単体実行の結果）、つながり。手で組むときは「設定を変える → そのノードだけ試す → 結果を見る → 次のノードへ」を繰り返すので、フロー図を隠さずに右の欄だけで回せるようにする（2026-11-08、全画面の編集をやめた。#208 で設定が必須と使っているものだけになり、420px で足りるようになったため）。欄が狭いので、設定の名前は欄の上に置く。ダブルクリックとノードの追加は、最初の設定欄にカーソルを入れる。PAD のような別ウィンドウは、フロー図が隠れ窓を見失いやすいので作らない。
- 何も選んでいないとき：フローそのもの。基本（名前・説明）、変数（入力・出力・内部）、実行の設定（既定のタイムアウト・エラー時）。
- 部品を選んだとき：種類（ブラウザ／デスクトップアプリ）、名前、画面での見つけ方の一文、使っているノード、「部品を編集」。名前・「画面で選ぶ」・見つけ方の欄・削除は「部品を編集」で開く画面にまとめる（主な操作の「画面で選ぶ」は大きなボタン）。
- 上端に「フロー › ノード」の道筋を出し、フロー名を押すとフローの表示に戻る。

ノードの設定（インスペクターとノードの画面の中央）は、見出しを重ねない 1 本の欄の並びにする。先頭にそのノードに要る設定（必須）と値の入っている設定だけを出し、ほかのもの（任意の設定・結果を保存する変数・無効化・待ち時間・再試行・エラー時・メモ）は一つの「＋ 設定を追加」から名前を選んで 1 行ずつ足す（n8n の「Add option」、PAD の「詳細」と同じ考え）。足した行は × で外せる。表示名は種類名のそばでその場で直す。設定の意味の説明は欄の下に常に出さず、名前の右の「?」のツールチップにする（毎回読むのは最初の数回だけなので）。画面上の対象は、値の入った項目だけを出し、空の項目は「詳しく指定」に畳む（空の対象は従来どおり主な項目を出す）。ノードの画面では「変数のつながり」は左の「使える値」とインスペクターにあるので出さない。「JSON で編集（上級）」は欄の下の端に小さく置く。

ノードの画面は、左に「使える値」（前のノードの結果・繰り返し中の行の列。押すと最後に触った欄に入る）、右に実行結果を置く。右上のボタンは二つで、強さは同じ（枠線）：

- **ノードの単体実行**：このノードだけを実行する。前のノードは実行しない。読む変数には前回の実行の値（なければ初期値）を使い（`lib/stepTest.ts`）、値のない変数があれば押せず、理由をツールチップに出す。実行の記録（`runs/`）には残さない。AI の `test_step` と同じ一ノードのフローで動かす（`shikigami_runtime::single`）。
- **ここまで実行**：先頭からこのノードまで実行し、このノードの直後で一時停止する。前のノードも実際に動く（メールの送信なども）ので、そう書いたツールチップを付ける。

ノードの右クリックには「ここまで実行」と「ここから実行」を置く。**ここから実行**は前のノードを実行せず、このノードからフローの最後まで実行する（ブレークポイント・エラーでの一時停止はいつもどおり）。変数は直前の実行がこのノードに来たときの値（来ていなければ最後の値、シークレットと一部しか残っていない値は初期値）で始める（`lib/startAt.ts`）。グループと try の中からは始められ、繰り返し・分岐・catch / finally の中からは何回目・どちらの枝か決まらないので押せない（Runtime の `RunOptions::start_at`、`work/` は空にしない）。

性質ではないものは入れない。記録と版はフローの過去なので「履歴」（リビジョンから開く）、検証結果はフロー全体の一覧なので下パネル、「サブフローにまとめる」は操作なのでノードのそばに置く。

### 3. 操作は対象のそばに置く

選んだノードの並べ替え・まとめる・削除は、そのノードの見出しの右に出す。上下の中央にはフローの線が通り、見出しより下の行の横には変数のチップが並ぶので、見出しの横が空いている。ポインターはもうノードの上にあるので遠くへ動かさなくてよく、選んでいないときは出ないので押せない灰色のボタンも並ばない。

ノードを足す場所もそのそばで決める。足すボタンはどこでも同じ「＋ ノード追加」（文字付き、同じ形）にし、場所によって「＋」だけのものと混ぜない。フロー図の線にポインターを置くと線の上に「＋ ノード追加」が出て、押すとその線の先のノードの前に足す（分岐の見出しのある線では見出しの右）。枠の中の最後に足すボタンは、その枠の中（見出し・中のノード・何もないところ）を指しているあいだだけ出し、隠れているときは線がそのまま通る（枝や繰り返しが多いフローで「＋」が並んでうるさくならないように）。フローの最後のボタンは 1 つしかないのでいつも出す。中身が空の枠は大きな「＋ ノード追加」をいつも出し、押すとその枠に足すパレットが開く。指さないと出ないボタンは、キーボードで選んだときにも出し、指せない人はドックの「ノード追加」（Ctrl+K）と右クリックの「ここにノードを追加」で同じ場所に足せる。どこからも選べないときは、選んだノードの次、何も選んでいなければフローの最後に足す。

開くものは開く場所のそばに置く。目次ボタンは目次が開く作業面の左上の角に浮かべ、開いた目次の見出しに ✕ を置く。リビジョンは履歴、検証は下パネル、AI チャットは窓の帯のまん中、検索の隣（打った言葉をそのまま頼めるように）。

### 4. 読む順に並べ、主ボタンで終える

帯の中は左から「どこにあるか → 何か → 状態はどうか → どう見るか → どうするか」の順に並べる。一番大事な操作（主ボタン）は帯の右端に置き、名前の長さが変わっても位置が動かないようにする。タイトルバーのフローの操作は「実行」、ページの見出し行は「新しく登録」で終わる。ウィンドウ操作はその上の地の帯の右端にあり、どの場所でも同じ位置にある。

### 5. 一つの面に塗りつぶしのボタンは一つ

| 強さ | 見た目 | 例 |
| --- | --- | --- |
| 主 | 青（`bg-primary` / `text-on-primary`）の塗りつぶし | タイトルバーの「実行」、一覧の「新規作成」、AI の変更の「確認して公開」 |
| 副 | 枠線 | 「ステップ実行」 |
| 補助 | 枠なし、ホバーで地色 | ドックの「ノード追加」、目次、元に戻す、↑ ↓、まとめる… |
| 選択中 | 薄い灰の地＋灰の枠（塗りつぶしにしない） | 切替（フロー図／手順書／変数）、タグ、繰り返しの種類 |
| 危険 | 朱の文字または枠 | 「中止」「変更を取り消す」、✕ はホバーで朱 |

インスペクターと下パネルの中の「変数を追加」「作成」などは副（枠線）にする。その面の主ボタンはタイトルバーの「実行」だから。一時停止の帯の「AI に直してもらう」も副（青い文字の枠線）で、主は「再実行」だけ。

フォームの終わりのボタンは右寄せで「キャンセル｜保存」（主ボタンが右端）。スケジュール・シークレット・新規作成で同じ。何かを新しく作るフォームは見出しを欄の上に置き、設定画面は 1 設定 1 行（名前｜入力欄）にする。

### 6. 一つの事実は一か所で示す

同じ数や状態を二か所に出さない。

- 確認待ちの件数：サイドバーの「確認待ち」の数だけ。
- AI からのログイン登録の依頼：サイドバーの「シークレット」の数だけ。
- 検証の結果：タイトルバーの「問題なし / エラー n 件 / 未設定 n 件 / 要対応 n 件」。押すと下パネルの検証結果が開く。
- フローの名前：タイトルバーだけ。インスペクターの見出しは「フロー」「フロー › ノード名」とし、名前を繰り返さない。
- 保存先：サイドバーの上端だけ（フォルダー名。全体のパスはツールチップと設定）。
- 更新があること：サイドバーの「設定」の点と、「SpellSheet ▾」の青い点（メニューの中に「更新があります」）。

### 7. バッジは人を待つものだけを数える

- 朱の数字：人の確認を待っている（確認待ち、記録の未確認）
- 橙の数字：人の入力を待っている（ログインの登録依頼）
- 青の点：見ておくとよいが、急がない（更新）
- 灰の数字：知らせるだけ（検証結果の件数）

登録済みのシークレットの数のような在庫の数には付けない。

### 8. 窓の帯は窓全体のものだけ

窓の帯には、どこを開いていても意味の変わらないものだけを置く：左に「SpellSheet ▾」、まん中に検索と AI チャット、右端にウィンドウ操作。開いているフローのこと（実行の状態・ノードの位置）はパネルの中に置く。言語・テーマ・バージョンは「SpellSheet ▾」のメニューと設定に置き、ステータスバーは作らない（毎日は切り替えないものに常に 28px を使わない）。保存先は「どこにあるか」なので、サイドバーの上端に置く。

### 9. 幅が足りないときは、外側から譲る

作業面（フロー図）を最後まで残し、幅 480px を下回らせない。足りなくなったら、外側の部品から次の順に譲る（`apps/studio/src/lib/fit.ts`）。

1. サイドバーをミニバー（アイコンだけの 44px の列）に畳む。消しはしないので、場所へはアイコンから 1 クリックで移れる。ミニバーの上端の開くボタン（Ctrl+B）で、サイドバーが作業面の上に一時的に重なって開き、場所を選ぶと閉じる（Linear・Notion の狭い画面と同じ）。手で畳んだサイドバーは、開くボタンで元の列に戻る。
2. 確認待ちの一覧を細い帯（44px）にたたむ。帯の » で同じように重ねて開く。
3. AI ペインを 380px から 320px に細くする。
4. それでも足りなければ、AI ペインがインスペクターの場所を借りる。AI ペインを閉じればインスペクターが戻る。

インスペクターはそもそも、ノードか部品を選んでいるとき・フローの設定を出したままにしているときだけ場所を取る（2026-11-08、Daiki「右ペイン常に表示されてるのやっぱりスペース的に厳しい」）。#208 の「フロー図を見たまま右の欄で編集」はそのまま：ノードを押せば右に開き、フロー図は隠れない。何も選んでいないときに幅を取り続けないだけ。

何も開いていないときはインスペクターの列そのものを出さない。ウィンドウの最小幅（960px）でも、この順で作業面 480px が残る。

サイドバー・確認待ちの一覧・インスペクター・AI ペイン・下パネルは、作業面側の縁のつまみをドラッグして大きさを変えられる（VS Code・Linear と同じ）。つまみは境界線の上に重なる細い帯で、ホバーとドラッグ中だけ青い線を出す。ダブルクリックで既定の大きさに戻し、矢印キーでも動かせる。変えた大きさは覚えておき、上の譲り方はその大きさで計算する。ドラッグで作業面を 480px より狭くはできない。

タイトルバーは狭くなると「変更履歴」「問題なし」「ステップ実行」の文字を記号に替える。フロー名と「実行」は文字のまま残す。部品の幅は決まった値にし、中身の長さで列が広がらないようにする。

### 10. 高さ（影）は意味で決める

| 高さ | 影 | 使う所 |
| --- | --- | --- |
| 1dp | `shadow-sheet` | 机に置いた紙：設定やシークレットの節、選ばれた切替 |
| 2dp | `shadow-node` | フロー図のノード |
| 4dp | `shadow-raised` | 作業面に浮く道具：ドック、目次、ノードの操作、ズーム |
| 8dp | `shadow-lifted` | 持ち上げたもの：選んだノード、メニュー、ポップアップ |
| 24dp | `shadow-dialog` | ダイアログ、コマンドパレット、画像の拡大 |

サイドバーと確認待ちの一覧は机（paper）、作業面は一段低い机（desk）、インスペクター・タイトルバー・ペインは紙（sheet）。

### 11. 色は役割、角は 4〜8px

窓の地（`bg-frame`、薄い灰）に窓の帯とサイドバーを直に置き、作業の面（タイトルバーから下）は 1px の枠と 8px の角の浮いたパネルにする（Linear と同じ）。ウィンドウ操作（最小化・最大化・閉じる）はパネルに入れず、パネルの上の高さ 40px の窓の帯に置いて、Windows のどの窓とも同じく窓の右上の角にぴったり付ける（最大化した窓で右上の隅へマウスを投げれば「閉じる」に当たる）。帯の残りは窓をつかんで動かす場所。浮いている部品（プロジェクト棚・ドック・目次）の影は薄く、主ボタンは高さ 28px・文字 13px の中太。英数字は Inter、かなと漢字は Noto Sans JP。

- 青（brand）＝AI、橙＝実行中・変更あり・人の入力待ち、朱＝エラー・危険・人の確認待ち、緑＝成功・問題なし。ノードは白い面に 1px の灰の枠、アイコンと文字は灰と黒だけで、ノードの種類で色を塗り分けない。色が付くのは状態（完了＝緑の点、実行中＝橙、エラー＝朱、未設定・要対応＝橙の点線の円、AI の未確認の変更＝青の半円）と選択（青の枠）だけ。変数の種類の色は、値の中の変数の札の点と、つなぎ口が光るときだけに使う。例外は 3 つ。判定の六角形（繰り返し・条件分岐・値による分岐）は薄い黄色の面と黄色の枠にする（フローチャートの判定の色。図の中で「ここで分かれる・判定している」を一目で探せるように。橙より明るい黄色にして、実行中の橙とは混ぜない）。ノードのアイコンは種類の色（ノード追加の一覧と同じ `CATEGORY_COLOR`）にして、どこから出したノードかをつなげる（面や枠は塗らない）。エラー処理の「失敗したとき」の札は朱の文字と薄い朱の面にして、失敗したときの道筋を探せるようにする（ノードは塗らず、エラーの印と見分けられるようにする）。「はい」を緑・「いいえ」を赤にはしない（緑は成功、朱はエラーの印なので、「いいえ」がエラーに見える）。
- ロゴの 4 色は、フローのフォルダーのファイルの役割にも使う：水色＝入力（input/）、青＝設定（config/）、緑＝テンプレート（templates/）、橙＝出力（output/）。棚の印、ノードのファイルの項目の左の線と地の色だけに使い、飾りには使わない。
- フロー制御（繰り返し・条件分岐・値による分岐・エラー処理・並列実行・グループ）は「見出し付きの枠」1 つの決まりで描く。制御のノードは枠の上辺の見出しそのもので（アイコン・名詞・名前・条件式、右端に「＋ ケース」「＋ 最後に必ず」とたたむボタン）、別のカードを置かない。条件分岐と値による分岐は、見出しの下に繰り返しと同じ黄色の六角形（「amount > 10000？」「region は？」）を置き、枝はそこから分かれる（見出しには条件を重ねて書かない。たたんだときだけ見出しに出す）。枝は枠の中の列で、列の頭に短い見出し（はい／いいえ、実行／失敗したとき、その他。値による分岐のケースは値を書いた札で、押すとそのケースを選ぶ）。列の線は枠の下辺の上に置いた合流点（灰の点）で 1 本に戻ってから次へ進み、線が枠の内側から出ているようには見せない。エラー処理の「失敗したとき」は見出しから分かれない（最初にどちらかを選ぶのではなく、「実行」のどのノードからでも失敗すれば飛ぶため）。「実行」の各ノードの横から点線を出して列の右で 1 本にまとめ、その上端から「失敗したとき」の列（少し下げて置く）へ入れる。エラー処理の「最後に必ず」は、実行／失敗したときの列が合流した後に縦に続ける（どちらのあとにも必ず動くため、横に並べない）。繰り返しの終了・次の繰り返しへ・エラーを出すのあとには線を引かず（その下へは進まないため）、ノードの下に「ここで抜けて「繰り返し終了」へ」などと添える（繰り返しの終了を指すと、行き先の「繰り返し終了」の帯が濃くなる）。条件まで待機の確かめる手順も、繰り返しと同じ戻り線（「もう一度確かめる」）と出口（「条件を満たしたら」）で描く。繰り返しは薄い地を敷き、判定の場所に六角形の札（中に「次の 1 件がある？」、回数なら「まだ回数が残っている？」、条件なら条件式。幅は問いの長さに合わせ、線は左右のとがった角に出入りする）を置いて、繰り返しの種類と判定のタイミングが一目で分かるようにする。先に判定する繰り返し（リスト・回数・条件）は札が本体の上にあり、「はい」で本体へ、本体の終わりから枠の左端を上がる点線（「次の 1 件へ」「次の回へ」）が札の左に戻り、「いいえ」は枠の右端を下りて枠の下端の帯「繰り返し終了」に入る。いつ抜けるか（「すべて終わったら」「条件が外れたら」「回数を終えたら」）は、その「いいえ」の線が帯へ曲がるところに枠の中で添える（左の「次の 1 件へ」と対になる）。繰り返しの終了で抜けたときも行き先は同じ帯で、「すべて終わったら」は通らない（途中で抜けたのに「すべて終わった」と読めないように）。帯は見出しと同じ白い面で、線は帯を貫いて次のノードへ進む。実行のあとも帯の右に何回回ったか（「12 件中 12 件」「12 件中 7 件目で抜けた」「3 回中 2 回目でエラー」、実行中は「3 / 12 件目」）を残し、繰り返しの終了で抜けたときは「いいえ」の線を光らせない。入れ子の内側の繰り返しは、最後に回ったときの回数を出す。判定から出る線の答え（はい／いいえ）は、線が判定から出てすぐのところに、判定と同じ黄色の札で線の上に置く。札は実行の跡の色の線より手前に重ねる（線が札の上を通らない）。はいといいえで色は分けない（緑・朱は実行の跡の色なので紛れる）。あとで判定する条件まで待機は札が確かめる手順の下にあり、「いいえ」で左端を上がって手順の頭へ戻り、「はい」で下へ出る。戻り線は枠の中だけを通り、本体が空なら引かない。繰り返しの見出しか判定、または枠の中の何もないところを指す（または選ぶ）と、戻り線の点線が流れの向きに動いて、戻っていくことを見せる。条件分岐・値による分岐も、見出しか判定か枠の中の何もないところを指すと、ほかの枝のノードと線を薄くして、枝を 1 本ずつ順に浮かび上がらせ、どれか 1 本だけを通ることを見せる。線の色は「実行がここを通った」（緑・朱・橙）にだけ使うので、指しただけで線の色を変えることはしない。面の大きいノードの明暗なら、大きなフローでも気づける。いつも動かしておくと大きなフローでは目がうるさく、実行中の印とも紛れるので、指したときだけにする。分岐は選んで設定を編集しているあいだ点滅し続けると邪魔なので、選んだだけでは動かさない。OS で動きを減らす設定にしている人には動かさない。次のノードへの線は枠の下辺（繰り返しなら「繰り返し終了」の帯）から出る。条件まで待機は「条件を満たしたら」を枠の外の線に添える。枠は入れ子になっていても深さに関係なく同じ見た目・同じ動きにし、指したところをいちばん内側で囲む枠が反応する（中のノードを指したときはそのノードだけ）。見出しは枠の上辺なので、制御のノードを選ぶと枠全体の縁が青くなり、指すと枠全体の縁が濃くなる（見出しだけ色が変わると、どこまでがその制御か分からないため）。たためば見出しだけになり「中に N ノード」と出る（この PC だけの表示）。サブフロー呼び出しは紙を 2 枚重ねた形にして、中にフローを抱えていると分かるようにする。
- 実行の跡：実行が通ったノードの枠と線を、同じ役割の色（緑＝通った、朱＝止まったノードへの線、橙＝実行中）で塗る。終わったあとも残し、フローを編集したとき・次の実行・別のフローを開いたときに消える。手で消すのは下パネルの実行ログの「図の色を消す」（右クリックにも同じもの）。
- 虹色はロゴマークだけ。
- 角は小さく落ち着いた丸み（Linear にならう）：札・入力欄 4〜5px、ボタン・ノード 6px、枠・パネル・ダイアログ 8px。円は状態の印とブレークポイントだけ。
- 薄い色で目を疲れさせない。補足の文字は白地で 4.5:1 以上（slate-400 以上、本文の補足は slate-500）、枠線は slate-200。灰色は `index.css` の slate を一段濃くしてあるので、新しく別の灰色を足さない。使っていないものを薄くするときも opacity は 75% まで。
- ダークテーマの地はスレートグレー（青みを抑えた灰色）。紺や青の地にはしない。青は AI などの意味のある印だけ。

### 12. 文字か記号か、大きさ

- 業務の言葉で呼ぶ操作は文字にする（「実行」「ノード追加」「シークレット」「AI チャット」）。説明調・話し言葉にしない。
- 形でわかるものだけ記号にする（↑ ↓ ✕ ↶ ↷、ウィンドウ操作）。サイドバーの場所は文字に小さなアイコンを添える。アイコンは lucide にそろえ、手描きの SVG を足さない。画面の中で別の意味に使っているアイコンと似た形は選ばない（設定に歯車を使うとテーマ切替の太陽と見分けにくいので、スライダーの形にする）。記号だけのボタンには `title` を付け、ショートカットを書き添える。
- タイトルバー・インスペクターの見出し・確認の見出しはどれも 40px にそろえ、下の線を一本につなげる。帯の中の操作は 24〜32px。

### 13. フローの線

ノードの順番の線は 1.5px の薄い灰。変数の値の線は、選んだノード・指した変数のものだけを細く引く。変数の値の線はノードの裏を通さない。書くノードの右から出て、読むノードの左側から入り、そのあいだはノード・枠の見出しの横と間の隙間だけを通る（曲がる回数が少なく、短い道を選ぶ。`lib/linkRoute.ts`）。プログラムの言葉（forEach、try、if…）は図に出さず、線の札は「受注一覧 の 1 件ずつ → 受注」「失敗したら」のように普通の言葉で書く（英語名はパレットの検索語に残す）。

枠はノードのすぐ外を囲み（横の空きは線と変数の線が通る分だけ）、見出しの名前・条件が切れずに読める幅までは広げる。線はノードの上下の中央から出入りし、曲がり角を越えて先へ伸ばさない（分岐の横線より下へはみ出さない）。線の端を受ける点（ハンドル）は手でつなぐものではないので描かない。

フローは「開始」の札から始まり「終了」の札で終わる（フローチャートの端子）。札はノードではなく小さな角丸の札（ピル形）で、選択・削除・右クリックのノード操作・「ここから実行」の対象にしない（押すとフローの設定を開く）。札は飾りにせず、開始には変数の向きを「受け取る」にした値、終了には「返す」にした値を並べ、そこから読むノード・そこへ書くノードへ変数の線を引く（サブフローの入口と出口がひと目で分かる）。最後のノードの下の「＋ ノード追加」は枠の中の最後と同じ形で（こちらはいつも出す）、線はそこを通って終了へ入る。繰り返しの終了・エラーを出すで終わる道は終了へつながない。実行の跡の線は終了まで伸び、最後まで通ったかが分かる。「繰り返しの終了」「ブラウザ終了」などの終了系ノードとは、形（ピル形・アイコンなし）で見分ける。

### 14. ノードを探す（パレット）

ノードはパレット（Ctrl+K・ドックの「ノード追加」・線・枠とフローの最後・空の枠の「＋ ノード追加」・右クリックの「ここにノードを追加」）一つで選ぶ。入口が違っても中身は同じにする（`components/CommandPalette.tsx`、`lib/palette.ts`、アイコンは `lib/nodeIcons.ts`）。

- 画面の真ん中に暗幕を掛けて出さない。押したもの（「＋」・枠・ドック。Ctrl+K なら選んだノード）のすぐ下か上に浮かべ、フロー図と足す場所を隠さない（8dp）。外を押すか Esc で閉じる。
- 左に分類をいつも並べる（他の RPA のアクティビティの木と同じく、一覧を開き直さずに分類を見比べられる）。いちばん上の「よく使う」を開いた状態で出る。分類を押すと右にその分類のノード。
- 分類は「何を操作するか」で分ける。見出しは「操作するもの（ブラウザ・Excel・Word・Outlook・ファイル・デスクトップアプリ・Web API・データベース・ダイアログ・システム）→ 流れの制御（制御・サブフロー・変数・待機・ログ）→ 値の加工（文字・数値・日付・表・リスト）」。Office はアプリごとに分ける（人は「Excel」で探す）。「サブフロー」には入力か出力を持つフロー（開いているもの以外）を名前でノードとして並べ、選ぶとその呼び出しを足す。プラグインの分類は最後。
- 操作するノードと流れを制御するノードを 1 つの並びに混ぜない。「よく使う」は「よく使う操作」（4 件）と「流れの制御」（小さいタイルで 2 列）に分け、検索結果も同じ見出しで分ける（いちばん合うものの見出しを先に）。
- 分類の中は名前順でなく使う順に、用途の見出し（開始・終了／操作／読み取り／書き込み／待機…）の下に並べる（`lib/palette.ts` の `SUBGROUPS`）。
- 直前のノードの次によく使うノード（「行の読み取り」の次の「繰り返し（リスト）」など、`NEXT`）を「よく使う」の上に出す。
- 各行はアイコン（分類の色の地）・名前・何をするかの一文（`locales/stepHelp.*.ts`、人向けの言葉。レジストリの説明は AI 向けなので出さない。名前を繰り返すだけの一文にしない）。同じ名前（「クリック」）が別の分類にあるので、「よく使う」と検索では行の右に分類を出す。値の加工の行に式は出さない。
- 一覧の下に、選んでいる（マウスを置いた）ノードの一文の全文・必須の設定・結果を返すか・中に入れるノードを出す。足して開くまで分からない、をなくす。
- 検索は名前・別の呼び方（エクセル、ループ、待つ…）・英語の名前・説明を見て、名前に合うものを上に並べる。カタカナ／ひらがな、全角／半角は区別しない。IME で変換する前のかな（まつ、よむ）やローマ字（kurikaesi）でも見つかる。カタカナの語の途中には当てない（「ログ」で「ダイアログ」を出さない）。名前か別の呼び方に当たるノードがあれば、説明にだけ当たるものは出さない。新しく打ち始めた検索はすべての分類から探し、左の分類で絞れる。
- 下端に「追加する場所」を出す（「メッセージ表示」の次、など）。どこに入るかを押す前に確かめられる。
- キー：↑↓ 選ぶ、Enter 追加、←→ 分類を移る（検索していないとき）、Esc 検索を消す／閉じる。

### 15. 右クリック

ブラウザの右クリックメニュー（戻る・最新の情報に更新・印刷・開発者ツールで調査する）は出さない。デスクトップのアプリとして意味がないため。右クリックは「そのものに効く操作」を、そのものの上で開く近道にする（`lib/contextMenu.ts`、`components/menus.ts`）。

- メニューに入れるのは、そばのボタン・インスペクター・キーにすでにある操作だけ。同じ言葉とショートカットを書き添え、メニューにしかない操作は作らない。
- 開く前に右クリックしたものを選ぶ（ノード・空きの枠）。何に効くかがインスペクターでも見える。
- 置き場所ごとの中身：

| 右クリックしたもの | メニュー |
| --- | --- |
| ノード（フロー図・手順書） | サブフローを開く・中を表示／たたむ（呼び出しのとき）、切り取り・コピー・後ろに貼り付け・複製、上へ・下へ、繰り返し（リスト）・繰り返し（回数）・条件分岐・エラー処理・グループで囲む、無効にする、ブレークポイント、AI に聞く、ID をコピー、削除 |
| サブフローの中のノード（読むだけ） | ブレークポイント、ID をコピー |
| 空きの枠 | ここにノードを追加、貼り付け |
| フロー図の地 | ノード追加、ノードを貼り付け、記録、元に戻す・やり直す、全体を表示、図の色を消す・ブレークポイントをすべて外す（あるときだけ。実行ログの上にも同じボタン）、目次（サブフローの中では「元のフローに戻る」） |
| 変数（ノードのチップ・変数の表） | 名前をコピー、変数の設定、書き込むノードへ（表）、変数を削除 |
| フローの一覧の行 | 開く、複製、ID をコピー、削除（もう一度押して確定） |
| プロジェクトのファイル | 開く、アプリで開く、エクスプローラーで表示、パスをコピー、名前を変更、削除 |
| 入力欄 | 切り取り・コピー・貼り付け・すべて選択 |
| 選んだ文字 | コピー |
| それ以外 | 何も出さない |

- 流れの制御は「先に置いて中を埋める」より「並べた操作を後から囲む」ことが多いので、選んだノード（Shift+クリックで続いた複数も）をその場で繰り返し・条件分岐・エラー処理・グループの中に入れる「〜で囲む」を右クリックに置く（store の `wrapSelected`、1 回の変更なので元に戻すも 1 回）。囲んだ制御ノードは設定が要れば設定画面を開く。
- 「サブフローにまとめる」も同じ選び方に乗せる：右クリックの「〜で囲む」の隣と、選んだノードのそばの「まとめる…」から開き、Shift+クリックで選んだ範囲があればそれをそのまま使う（範囲を選び直す欄は出さない）。1 つだけ選んでいるときは「このノードだけ／ここから N ノード」と、Shift+クリックで広げられることを書き添える。開いたまま Shift+クリックすれば範囲が広がる。複数選んでいる間は、ノードのそばの道具に「N ノード選択中」を出して、操作が全部に効くことを見せる。囲んで選ぶのは Shift+ドラッグ（ふつうのドラッグは画面の移動のまま）。まとめられるのは同じ枠の中の続いたノードだけなので、囲んだノードは「同じ枠の中の、先頭から最後まで」に揃える：枠の中だけを囲めば枠の中、枠の外まで囲めば枠ごと、分岐の両側や制御の見出しと中身なら制御ノードごと、値による分岐のケースは分岐ごと（`lib/stepClipboard.ts` の `boxRange`）。ノードのそばの道具のクリックはノードのクリックとして扱わない（選んだ範囲が消えないように）。
- ノードのコピー・貼り付け：Ctrl+C / Ctrl+X / Ctrl+V / Ctrl+D（複製）。Shift+クリックで同じ枠の中の続いたノードをまとめて選び、コピー・削除できる。クリップボードにはフローと同じ形の JSON（`steps` と、使っている名前付きの部品 `parts`）を置くので、別のフロー・別の窓にも貼れ、AI のチャットに貼ってもそのまま読める。貼ったノードは ID を付け直し、フローに無い部品だけ足す（`lib/stepClipboard.ts`）。ページの文字を選んでいるときの Ctrl+C は文字のコピーのまま
- 見た目は持ち上げたもの（8dp、`shadow-lifted`）、アイコンは lucide、危険な操作は朱で最後に置く。↑ ↓ Enter Esc で操作できる。
- 開発版だけ、Shift を押しながら右クリックするとブラウザのメニュー（「開発者ツールで調査する」）が出る。F12・Ctrl+Shift+I もそのまま使える。

### 16. 値の加工と式の入力

現場の人に式を書かせない。フローに残すのは今までどおり「変数への代入」の `expression`（AI が書くのと同じ一つの書き方、[ai-authoring.md](ai-authoring.md)）で、Studio はその見せ方と入れ方を変える（`lib/transforms.ts`、`components/TransformForm.tsx`、`components/ExpressionField.tsx`）。

- **加工のフォーム**：式がよく使う形（`sum(map(rows, r => num(r.金額)))`、`trim(text)`、`filter(rows, r => num(r.金額) >= limit)` など 27 種）なら、インスペクターでは「加工：表の列を集計／集計：合計／表：rows／列：金額」のフォームで出す。変数はドロップダウン（前回の実行の値つき）、表の列は前回の実行の値から候補を出す。フォームは式を書き直すだけ。AI が書いた式も同じ形ならフォームで出る。
- フロー図・手順書の文と見出しもフォームと同じ言葉にする（「total に rows の「金額」の合計を入れる」、見出し「表の列を集計」）。
- パレットの「文字・数値・日付・表・リスト」は、このフォームの加工を並べる。追加すると既定の値で式が入り、フォームで変数を選び直す。
- 形に合わない式、条件（`condition`）・繰り返しの対象（`items`）などの式の欄は、式の入力欄で支える：
  - 変数は型の色の帯で示し、文字（緑）や数と見分けられるようにする。フローにない名前は朱の波線。
  - 入力中に変数・表の列（`r.` の後）・関数を候補に出す（関数は日本語の名前と説明、かなでも探せる。Ctrl+Space でも開く）。
  - カーソルのある関数の引数と説明を欄の上に出す（`locales/functionHelp.*`。Core の関数一覧は AI 向けなので出さない）。
  - 欄の下に、前回の実行の値で Core が計算した結果を出す（`eval_expression`）。値がまだなければ「実行すると…」、書き間違いは実行エラーと同じ言い換えで出す。大きい値は先頭だけ記録されるので、その場合は「一部で計算」と書き添える。
- 新しい加工を足すときは `TRANSFORMS` にテンプレートを足し、`locales/transforms.{ja,en}.ts` に名前・説明・文・項目名を書く。テンプレートは AI が書く普通の形にする（Studio のための書き方を作らない）。

### 17. ファイルはドラッグで渡す

ファイルの名前を打たせない。プロジェクトのファイル（プロジェクトの棚、ノードの画面の「このフローのファイル」）とエクスプローラーのファイルは、置いた先で意味が決まる（`components/FileDrag.tsx`、`lib/fileDrop.ts`）。

- ファイルの設定欄：そのファイルのパス（フローのフォルダーからの相対パス）が入る。フォルダーの外のファイルは棚に取り込んでから入れる。フォルダーの設定欄にはファイルのあるフォルダー。
- フロー図：そのファイルを読むノードを作る（ノードの上なら直後、空のブロックならその中、何もない所なら最後）。読むノードのない種類は取り込むだけ。
- プロジェクトの棚：エクスプローラーのファイルを、その棚（または名前から振り分けて）に取り込む。
- ドラッグ中は受け取れる欄を点線で囲み、ポインターの横に「ここに入れる」「このファイルを読むノードを作る」と出す。Studio の中のドラッグはポインターで追う（Windows では、エクスプローラーからのドロップを受けている間は HTML のドラッグ＆ドロップがページに届かない）。

### 18. 値は指を止めると中身が見える

画像・表・長い文字の値は、ポインターを 300ms 止めると中身をポップオーバーで見せる（`components/HoverPreview.tsx`）。画像のパス（`png/jpg/gif/webp/bmp`）と画像のデータ（`data:image/…`・PNG/JPEG などの base64）はサムネイル、Excel・CSV は先頭 5 行、テキストファイルは冒頭、画面で省いた長い文字は全文。相対パスはフローのフォルダー（`flows/<id>/`）から、フルパスはそのまま読む（Tauri `preview_file`）。ファイルが無ければ「見つかりません」と赤で出す。

- 出す場所：フロー図の設定欄（画像で指す場所・部品の画像も）、変数の札の値、変数の一覧、止まった実行の変数、ノードの画面の結果、実行画面の出力、ファイル一覧の画像、部品の一覧
- 新しく値を出す所は、`<HoverPreview value={…}>` で包む。中身を見せられない値はそのまま描かれる。ポップオーバーの中に出す値は `ValueView` が画像・表を自分で並べる
- 画像はポップオーバーで最大 560×400（窓が狭ければ窓に合わせて縮む）、ノードの画面の結果では欄の幅いっぱい（高さ 360px まで）。1920×1080 の画面の表や文字が読める大きさにする（以前の 280×200 では読めず意味がなかった）
- 画像は押すと拡大表示（`components/ImageViewer.tsx`、`openImage`）で開く。窓いっぱいの 24dp のダイアログで、最初は「画面に合わせる」（小さい画像は拡大しない）、「等倍」、ホイールでポインターの位置を中心に拡大・縮小、ドラッグで移動、ダブルクリックで合わせる⇔等倍、Esc・外側を押すと閉じる。2 倍以上ではピクセルを四角のまま見せる（切り取った画像を点まで確かめられるように）。読み込みは押してから元の画像を読み直す（ポップオーバーは縮めた画像だけを持つ）。画像の下に「クリックで拡大」と添える
- フロー図の変数の札の値のポップオーバーはポインターを受けないので、札を押すと最後の値の画像を拡大表示で開く。一時停止中の画面のサムネイルも同じ拡大表示を使う
- 押す・ホイール・キーで閉じる（図を動かすと指す物がずれるため）。ポップオーバーの中の画像やスクロールは閉じない

## 新しいボタンや画面を足すときの手順

1. 何に効くかで区画を決める（骨組みの表、原則 1）。仕事の種類が新しいなら場所（サイドバー）、設定なら設定の節、選んだものの性質ならインスペクター。
2. 「今後の機能の置き場所」に載っていれば、それに従う。
3. 区画の中では読む順（原則 4）で位置を決める。
4. 強さを決める（原則 5）。その面にもう主ボタンがあれば、副か補助にする。
5. 同じ事実をもう出している所がないか確かめる（原則 6）。数を出すなら人を待つものか確かめる（原則 7）。
6. 文字か記号か、`title` とショートカット、日英の文言（`locales/{ja,en}.ts`）を用意する。
