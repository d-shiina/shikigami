# Studio の画面の骨組みと決まり（設計メモ）

目的：Studio のボタンや表示を「空いている所」に置かない。画面全体を決まった骨組みで分け、どの機能も「何に効くか」で置き場所が一つに決まるようにする。今後の機能（実行履歴、スケジュール実行、プラグイン、通知など）も、この骨組みのどこに入るかを先に決めておく。

見た目の土台（ロゴに合わせた白地・濃紺文字、Material Design の高さ、角 2〜4px、虹色なし、Noto Sans JP）は `apps/studio/src/index.css` の冒頭にある。このメモは、その上で「何をどこに置くか」を決める。

## 骨組み

```
┌ サイドバー ──────┬ タイトルバー ──────────────────────────────────────────────┐
│ ●保存先      ⇤ │ 名前 リビジョン▾ ✓検証   [フロー図|手順書] ステップ実行 [▶実行] │ Claude Code ─ □ ✕ │
│ 確認待ち      2 ├──────────────────────────────────────────┬─────┬────┤
│ シークレット     │ [目次]  作業面（フロー図） [↑ ↓ まとめる… ✕]  │ イン │ AI │
│ シナリオ ＋追加 │                                             │ スペ │ ペ │
│  検索           │        [＋ ステップ追加 | ↶ ↷]（ドック）    │ クタ │ イ │
│  ▸ シナリオ…    ├ 下パネル：実行ログ | 検証結果 ──────────── ✕ ┤ ー  │ ン │
│ 設定            │                                             │     │    │
├─────────────┴──────────────────────────────────────────┴─────┴────┤
│ AI の動き                              実行の状態  手順 3 / 12  JA EN  テーマ  v0.1.0 │
└ ステータスバー ─────────────────────────────────────────────────────┘
```

| 区画 | 役割 | 置くもの |
| --- | --- | --- |
| サイドバー（左端、上端まで、240px） | どこにあるか・どの仕事をするか | 上端にロゴと保存先（押すと設定）と隠すボタン、確認待ち・シークレット、シナリオの一覧（追加・検索）、下端に設定 |
| タイトルバー | 今開いているものと、それへの操作 | シナリオ名・リビジョン（履歴を開く）・検証、表示の切替・ステップ実行・実行、AI ペインの開閉、ウィンドウ操作。ページの場所ではページ名。サイドバーを隠しているときは左端に表示ボタン |
| 確認待ちの一覧 | 確認待ちの場所で何を開くか | サイドバーと作業面の間に出る |
| 作業面 | 作業そのもの | フロー図／手順書、目次（左上）、選んだ手順の操作、ドック、ズーム |
| 下パネル | 経過と結果の一覧 | 実行ログ、検証結果 |
| インスペクター（右） | 選んだものの性質 | 手順を選べば手順、何も選ばなければシナリオ |
| AI ペイン（右端） | どの場所からも使う相棒 | Claude Code との会話 |
| ステータスバー | 報告と見た目の切替 | 保存先、AI の動き、実行の状態、手順の位置、言語、テーマ、バージョン |
| ダイアログ | 今の作業を止めて答えるもの | 履歴（記録・版）、コマンドパレット、AI からのログイン登録依頼 |

### 場所（サイドバー）

Linear・Notion と同じく、左は 1 本のサイドバーにまとめる。アイコンだけの列と一覧の列を二重に並べない。場所は「仕事の種類」ごとに一つで、文字とアイコン（lucide、16px、線幅 1.75）の行で示す。場所を切り替えると、サイドバーより右がすべて入れ替わる。

- **シナリオ**：サイドバーのシナリオを押すと開く。作業面・インスペクター（名前と操作はタイトルバー）。作る・直す・試す。
- **確認待ち**：確認待ちの一覧・作業面（AI の変更に印）・右に確認の判断（残す／差し戻す／取り消す）。
- **シークレット**：登録済みのログイン情報と登録フォーム。
- **設定**（下端）：保存先、表示（言語・テーマ）、AI エージェント、バージョンと更新。仕事ではないので、仕事の場所から離して下端に置く。

### 今後の機能の置き場所

先に決めておき、増えたときにボタンを散らばらせない。

| 機能 | 置き場所 |
| --- | --- |
| 実行履歴（過去の実行と証跡） | サイドバーの場所に「実行」を足す。実行の一覧はサイドバーと作業面の間、作業面がその実行のフロー図 |
| スケジュール実行・トリガー | 「実行」の場所の中のタブ。シナリオ側には、インスペクターのシナリオ表示に「スケジュール」の節を足す |
| 公開版（無人実行に使う版） | タイトルバーのリビジョンの隣に「公開版 n」を出し、履歴ダイアログの「版」から公開する |
| 前へ・次へ（開いたシナリオの行き来） | タイトルバーの左端 |
| 全体の検索（シナリオ・手順・シークレットを横断） | サイドバーの保存先の下に検索の行。Ctrl+K は手順の追加のまま、検索は Ctrl+P |
| プラグイン（ノードの追加） | 設定に「プラグイン」の節。シナリオで使うステップはコマンドパレットに並ぶ |
| 通知 | 人を待つものはサイドバーの場所の数、終わった知らせはステータスバー |
| 新しい種類の手順の設定 | インスペクターの「パラメーター」の中。専用ボタンは作らない |

新しい場所は `components/Sidebar.tsx` に 1 行足す。新しい設定は `components/SettingsPage.tsx` に節を足す。

## 原則

### 1. 置き場所は「何に効くか」で決める

上の表のとおり、範囲が広いものほど外側（上・左）、狭いものほど内側に置く。ボタンの位置を見れば、押したときにどこまで変わるかがわかる。サイドバーの場所はどのシナリオを開いていても意味が変わらず、タイトルバーのボタンは必ず今開いているシナリオに効き、手順のそばのボタンはその手順にだけ効く。

ウィンドウは一度に一つのシナリオを開くので、タイトルバーがそのシナリオの見出しと操作を兼ねる。Linear・Notion・Claude のデスクトップ版と同じく、上端は「サイドバー（保存先）」と「開いているものと操作（タイトルバー）」に分け、見出しのための帯をもう一段重ねない。作業面は縦に 40px 広くなる。

### 2. インスペクターは「選んだものの性質」だけ

インスペクターには、選んだものが「何であるか・どう動くか」だけを出す。

- 手順を選んだとき：種類と文（見出し）、AI の変更と検証の指摘（その手順のもの）、基本（表示名）、パラメーター、出力、つながり、実行の設定（無効化・タイムアウト・リトライ・エラー時）。ID は最後に小さく。
- 何も選んでいないとき：シナリオそのもの。基本（名前・説明）、変数（入力・出力・内部）、実行の設定（既定のタイムアウト・エラー時）。
- 上端に「シナリオ › 手順」の道筋を出し、シナリオ名を押すとシナリオの表示に戻る。

性質ではないものは入れない。記録と版はシナリオの過去なので「履歴」（リビジョンから開く）、検証結果はシナリオ全体の一覧なので下パネル、「サブシナリオにまとめる」は操作なので手順のそばに置く。

### 3. 操作は対象のそばに置く

選んだ手順の並べ替え・まとめる・削除は、その手順の見出しの右に出す。上下の中央にはフローの線が通り、見出しより下の行の横には変数のチップが並ぶので、見出しの横が空いている。ポインターはもう手順の上にあるので遠くへ動かさなくてよく、選んでいないときは出ないので押せない灰色のボタンも並ばない。

開くものは開く場所のそばに置く。目次ボタンは目次が開く作業面の左上の角に浮かべ、開いた目次の見出しに ✕ を置く。リビジョンは履歴、検証は下パネル、Claude Code は AI ペインが開く右端の真上。

### 4. 読む順に並べ、主ボタンで終える

帯の中は左から「どこにあるか → 何か → 状態はどうか → どう見るか → どうするか」の順に並べる。一番大事な操作（主ボタン）は帯の右端に置き、名前の長さが変わっても位置が動かないようにする。タイトルバーのシナリオの操作は「実行」、ページの見出し行は「新しく登録」で終わる。その右の AI ペインとウィンドウ操作は、どの場所でも同じ位置にある。

### 5. 一つの面に塗りつぶしのボタンは一つ

| 強さ | 見た目 | 例 |
| --- | --- | --- |
| 主 | 濃紺（ink）の塗りつぶし | タイトルバーの「実行」、ドックの「ステップ追加」、AI の変更の「残す」 |
| 副 | 枠線 | 「ステップ実行」 |
| 補助 | 枠なし、ホバーで地色 | 目次、元に戻す、↑ ↓、まとめる… |
| 危険 | 朱の文字または枠 | 「停止」「変更を取り消す」、✕ はホバーで朱 |

### 6. 一つの事実は一か所で示す

同じ数や状態を二か所に出さない。

- 確認待ちの件数：サイドバーの「確認待ち」の数だけ。
- AI からのログイン登録の依頼：サイドバーの「シークレット」の数だけ。
- 検証の結果：タイトルバーの「検証OK / エラー n 件」。押すと下パネルの検証結果が開く。
- シナリオの名前：タイトルバーだけ。インスペクターの見出しは「シナリオ」「シナリオ › 手順名」とし、名前を繰り返さない。
- 保存先：サイドバーの上端だけ（フォルダー名。全体のパスはツールチップと設定）。
- 更新があること：サイドバーの「設定」の点と、ステータスバーのバージョン表示。

### 7. バッジは人を待つものだけを数える

- 朱の数字：人の確認を待っている（確認待ち、記録の未確認）
- 橙の数字：人の入力を待っている（ログインの登録依頼）
- 青の点：見ておくとよいが、急がない（更新）
- 灰の数字：知らせるだけ（検証結果の件数）

登録済みのシークレットの数のような在庫の数には付けない。

### 8. ステータスバーは報告だけ

左に「AI と実行が何をしているか」、右端に「手順の位置 → 言語・テーマ → バージョン」。バージョンを押すと設定が開く（変えるのは設定でする）。保存先は「どこにあるか」なので、サイドバーの上端に置く。言語とテーマはよく切り替えるので、設定と同じものをここにも置く。

### 9. 幅が足りないときは、外側から譲る

作業面（フロー図）を最後まで残し、幅 480px を下回らせない。足りなくなったら、外側の部品から次の順に譲る（`apps/studio/src/lib/fit.ts`）。

1. サイドバーを隠す。タイトルバーの左端の表示ボタン（Ctrl+B）で、サイドバーが作業面の上に一時的に重なって開き、シナリオを選ぶと閉じる（Linear・Notion の狭い画面と同じ）。手で隠したサイドバーは、表示ボタンで元の列に戻る。
2. 確認待ちの一覧を細い帯（44px）にたたむ。帯の » で同じように重ねて開く。
3. AI ペインを 380px から 320px に細くする。
4. それでも足りなければ、AI ペインがインスペクターの場所を借りる。AI ペインを閉じればインスペクターが戻る。AI ペインを閉じている間は、インスペクターは必ず出す。

何も開いていないときはインスペクターの列そのものを出さない。ウィンドウの最小幅（960px）でも、この順で作業面 480px が残る。

タイトルバーは狭くなると「リビジョン」「検証OK」「ステップ実行」の文字を記号に替える。シナリオ名と「実行」は文字のまま残す。部品の幅は決まった値にし、中身の長さで列が広がらないようにする。

### 10. 高さ（影）は意味で決める

| 高さ | 影 | 使う所 |
| --- | --- | --- |
| 1dp | `shadow-sheet` | 机に置いた紙：設定やシークレットの節、選ばれた切替 |
| 2dp | `shadow-node` | フロー図の手順 |
| 4dp | `shadow-raised` | 作業面に浮く道具：ドック、目次、手順の操作、ズーム |
| 8dp | `shadow-lifted` | 持ち上げたもの：選んだ手順、メニュー、ポップアップ |
| 24dp | `shadow-dialog` | ダイアログ、コマンドパレット、画像の拡大 |

サイドバーと確認待ちの一覧は机（paper）、作業面は一段低い机（desk）、インスペクター・タイトルバー・ペインは紙（sheet）。

### 11. 色は役割、角は 2〜4px

- 青（brand）＝AI、橙＝実行中・変更あり・人の入力待ち、朱＝エラー・危険・人の確認待ち、緑＝成功・検証OK。手順や変数の種類の色は、手順の見出しとソケットだけに使う。
- 虹色はロゴマークだけ。
- 角はすべて 2〜4px。丸は状態の点とブレークポイントだけ。

### 12. 文字か記号か、大きさ

- 業務の言葉で呼ぶ操作は文字にする（「実行」「ステップ追加」「シークレット」「Claude Code」）。説明調・話し言葉にしない。
- 形でわかるものだけ記号にする（↑ ↓ ✕ ↶ ↷、ウィンドウ操作）。サイドバーの場所は文字に小さなアイコンを添える。アイコンは lucide にそろえ、手描きの SVG を足さない。記号だけのボタンには `title` を付け、ショートカットを書き添える。
- タイトルバー・インスペクターの見出し・確認の見出しはどれも 40px にそろえ、下の線を一本につなげる。帯の中の操作は 24〜32px、ステータスバー（28px）の中は 20px。

### 13. フローの線

線は手順の上下の中央から出入りし、曲がり角を越えて先へ伸ばさない（分岐の横線より下へはみ出さない）。線の端を受ける点（ハンドル）は手でつなぐものではないので描かない。

## 新しいボタンや画面を足すときの手順

1. 何に効くかで区画を決める（骨組みの表、原則 1）。仕事の種類が新しいなら場所（サイドバー）、設定なら設定の節、選んだものの性質ならインスペクター。
2. 「今後の機能の置き場所」に載っていれば、それに従う。
3. 区画の中では読む順（原則 4）で位置を決める。
4. 強さを決める（原則 5）。その面にもう主ボタンがあれば、副か補助にする。
5. 同じ事実をもう出している所がないか確かめる（原則 6）。数を出すなら人を待つものか確かめる（原則 7）。
6. 文字か記号か、`title` とショートカット、日英の文言（`locales/{ja,en}.ts`）を用意する。
