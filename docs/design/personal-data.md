# 個人情報の流出を抑える（設計メモ）

状態：**P1 と P4 を作った**（2026-11-08）。今の作りを経路ごとに調べた結果と、足せる機能の提案。Daiki の方針は「他社製品と同程度に守れていればそこまで頑張らない」。他社並み（Power Automate Desktop の「機密」変数、UiPath の「プライベート」、各社の記録の保持期間）にあたる P1・P4 だけ作り、ほかは見送り（§6）。

## 1. 考え方

- RPA が扱う個人情報の多くは**シークレットではない普通の値**（氏名・住所・電話・メールアドレス・メール本文・Excel の行・画面に出た顧客情報）。パスワードや API キーは「シークレット」として別に守っているが、普通の値は今は守っていない。
- 流出先は大きく 2 つ。
  - **PC の外**：AI の提供元（クラウド）、管理サーバー、通知の送り先、拡張機能が送る先、共有したファイルを受け取った人。
  - **PC の中に残る**：実行記録・ログ・失敗時の画面・work/output フォルダー。PC を使える人・共有フォルダーを見られる人に見える。
- いちばん大きいのは **AI の経路**。フローを作る・直すために、AI は画面・ファイル・実行結果を読む。ここで本物のデータを読むと、それはそのまま AI の提供元に届く。

## 2. 経路ごとの今の状態

| 経路 | 今どうなっているか | 残るリスク |
|---|---|---|
| シークレット（パスワード・TOTP・API キー・OAuth） | 値は AES-256-GCM で暗号化してワークスペースに保存、鍵は Windows 資格情報マネージャー（#136）。資格情報マネージャーから直接読むこともできる（#180）。AI・フローには名前だけ。ログ・エラー・記録・MCP の結果では `***`（`Vault::mask`）。パスワード欄は画面保存で黒塗り、ページのテキストからも除く（#171 で漏れを修正）。登録済みのサイト・アプリ以外には入力しない | ユーザー名は伏せない（画面に出るため）。同じ Windows ユーザーでログインできる人・マルウェアは鍵も読める。4 文字未満の値は伏せ字の対象外 |
| AI：Studio の AI チャット | AI の CLI の組込ツール（ファイル読み・シェル・Web）は切ってあり、Shikigami の MCP ツールだけ（Claude Code `--tools ""`、Codex は shell 無効、Gemini は組込除外、Copilot は Shikigami だけ）。登録済みパスワードを含む文面は送らない（`SECRET_IN_MESSAGE`） | MCP の結果に入る普通の値はそのまま AI に届く（下の行） |
| AI：MCP のツール | 次の結果は**普通の値をそのまま返す**：`get_run_logs`（`variableChanged` の値）、`get_run_status` の出力、`test_step` の出力（`excel.readRange`・`mail.*`・`pdf.readText` などは本物の中身）、`inspect_page`（ページのツリーと文字、`image: true` なら画面の画像）、`inspect_ui`（窓の中身、OCR の文字）、`read_project_file`（input/ の CSV など）、`get_flow`（変数の初期値）。シークレットだけ伏せる。証跡（observation）は PC に保存 | ここが最大の経路。顧客の画面を見ながら作る・本物の Excel で試すと、その中身が AI の提供元に届く。どこまで渡ったかは `audit/mcp.jsonl` に呼び出しの記録はあるが、中身は残らない |
| AI：Studio の外で使う Claude Code など | Shikigami からは止められない。AI のクライアントが自分のツールで PC のファイルを読める | 利用者の設定次第 |
| AI：MCP のない AI チャット（仕様書・貼り付け） | AI には仕様書と、「AI 向けにコピー」したフローだけ。秘密の初期値は含めない（#168） | 普通の変数の初期値・メモ・ノード名に書いた個人情報はそのまま渡る |
| 実行記録 `runs/<run-id>/` | `events.jsonl` に変数の値（1000 文字で切る）、`report.json` に出力。秘密だけ `***` | 普通の値はすべて残る。`records.keepDays` / `keepRuns` で消せるが**既定は消さない** |
| フローのフォルダーの `logs/` | 人が読むログ。変数の値の抜粋が入る。新しい 100 件を残す | `keepDays` が効かない（100 件まで残る）。共有ワークスペースだと他の人も見られる |
| 失敗時の画面保存（#157） | 失敗したページ・窓を `logs/<時刻>_failed.png` に保存。パスワード欄だけ黒塗り。`records.failureScreenshots: false` で止められる | 顧客情報が写ったまま残る。既定はオン |
| 手順書の画面（[manual.md](manual.md)） | Studio から全体を実行したときノードごとに撮り、この PC の `manuals/` に最後の完了した実行の分だけ残す。パスワード欄・シークレット・フローが入力した欄は灰色に塗る。ほかは「隠す」でぼかし・黒塗り。書き出すときは焼き込み、表と入力欄のぼかしが既定。`records.manualScreens: false` で止められる | 相手のシステムに初めからある個人情報は、人が隠すまで PC の中の画面には写っている |
| work/・output/ | work/ は実行の始めに空にする（`keepWork` で残す）。output/ は残る | output/ は利用者が消すまで残る |
| メール・Microsoft Graph の OAuth | トークンは暗号化して `secrets/oauth/`、出力・ログ・MCP に出さない | 読んだメールの本文・宛先は普通の値として記録・AI に届く（上の行と同じ） |
| 拡張機能（別プロセス） | 渡すのは設定値（テンプレート展開後）と runId。シークレットは `secretParams` かつ「使ってよい先」に `plugin:<名前>` があるときだけ。標準エラー出力は伏せ字。入れる前に「外へ送るデータ」（`external`）を見せる | 拡張機能は普通のプログラムなので、受け取った値をどこへでも送れる。`external` は自己申告で、守らせる仕組みはない |
| 管理サーバー・エージェント | 通信は https（http は localhost だけ）、要求ごとに Ed25519 の署名と時刻。送るのは伏せ字済みのイベントと報告、画面は送らない | イベント・報告に普通の値が入る。参考実装のサーバーは中身を 1 つのファイルに平文で持つ |
| 通知（Teams・Slack・Webhook） | フロー名・エラー・ノード・PC・時刻・版・run ID。出力の値は送らない | エラーの文に値が混ざることがある（例：見つからなかった文字） |
| 共有・書き出し（バンドル） | `export_flow` は版とサブフロー、フローのフォルダーのファイルを同梱（output/・work/・logs/ は除く）。秘密の初期値は含めない | **input/・config/・tests/ は同梱**。本物の入力ファイルやテストに使った本物の値も一緒に渡る |

### まとめ

- **シークレットはかなり守れている**。値は AI にも記録にも出ず、決まったサイト・アプリにしか入力しない。
- **普通の個人情報は守っていない**。AI・実行記録・ログ・画面保存・管理サーバー・共有ファイルに、そのまま出る。ここを抑えるのが今回の本題。
- Shikigami だけでは抑えられないもの：AI の提供元の扱い（学習に使わない契約・保存期間）、Windows のアカウントを使える人、Studio の外で使う AI クライアント、拡張機能の中身。これは「利用の決まり」として docs に書く。

## 3. 足せる機能（案）

### P1「個人情報」の印と伏せ字（推奨・最優先）

変数（入力・出力・途中の変数）に `personal: true` を付けられるようにする。Studio では変数の設定に「個人情報」のチェック。

- 印のある変数の値は、実行記録（`events.jsonl`・`report.json`）、`logs/`、エラー、通知、管理サーバーに送るイベントで**形だけ**にする：`"‹個人情報 12 文字›"`、表なら `"‹個人情報 30 行 × 5 列›"`。
- 秘密の伏せ字と同じく、その値が他の変数やエラーの文に混ざっても伏せる（`Vault::mask` と同じしくみを実行ごとに持つ）。
- `forEach` の項目変数・`saveAs` は、元の値に印があれば引き継ぐ（Excel から読んだ表に印 → 1 行ずつの変数にも印）。
- Studio の画面の上では、人には見える（実行中の値・一時停止中の値）。伏せるのは「記録に残る・外に出る」ところ。
- 理由：秘密の伏せ字（`secret: true`）とまったく同じ考え方なので、利用者にも AI にも覚えることが少ない。値ではなく「どの変数か」で決めるので、パターン検出のような取りこぼし・誤検出がない。
- 弱点：印を付け忘れると守れない。→ P2・P5 で補う。

### P2 AI に渡す値の段階を選べる（推奨）

`policy.json` に `ai.data` を足す。

| 値 | AI に渡るもの |
|---|---|
| `full` | 今と同じ |
| `personalMasked`（**既定にしたい**） | P1 の印がある値は形だけ。ほかはそのまま |
| `shapeOnly` | 実行結果・`test_step` の出力・ファイルの中身は**すべて形だけ**（型・長さ・件数・列名）。画面のツリーはボタン名などを残し、入力欄の値・表のセルを伏せる。`image: true` の画像は承認が要る |

- 効く場所：`get_run_logs`・`get_run_status`・`test_step`・`run_tests` の結果、`read_project_file`、`inspect_page` / `inspect_ui` の文字と画像、`get_flow` の初期値。
- AI はフローを作るのに中身はほとんど要らない（列名と件数があれば `forEach` は書ける）。値が要るときは、AI が理由を書いて人が承認する（今の `ask` のしくみを使う）。
- 理由：AI の経路が最大なので、ここを 1 か所の設定で締められるのが一番効く。「AI が作り、AI なしで動く」の考えとも合う（動くときに AI は中身を見ない）。

### P3 AI 用の見本データ（推奨）

AI の試し（`run_flow`・`test_step`・`run_tests`）は、本物の input/ ではなく**見本データ**（`tests/` か `samples/` に置いたダミーの Excel・CSV）で動かせるようにする。

- `policy.json` の `ai.realInput: allow | ask | deny`（既定 `ask`）。`deny` なら AI の試しは見本データだけ。
- Studio に「見本データを作る」：本物の Excel の列名と型だけ残して、値をダミーに置き換えた複製を作る（氏名→「山田 太郎 1」など）。
- 理由：伏せ字は「漏れたら隠す」だが、見本データは「そもそも本物を渡さない」。会社に説明しやすい。

### P4 記録の保持期間を既定で決める・`logs/` にも効かせる

- `records.keepDays` の既定を「消さない」から **90 日**にする（Studio の設定で変えられる。今の利用者には最初に一度だけ知らせる）。
- `keepDays` を `logs/`・失敗時の画面にも効かせる（今は 100 件まで残る）。
- 失敗時の画面保存は、P1 の印のある値が入った欄を黒塗りにする（パスワード欄と同じしくみ。ブラウザは入力した欄が分かるので確実、デスクトップは入力した要素だけ）。
- 理由：作り直しが小さく、残る期間が限られるだけでも「いつまで持っているか」を説明できる。

### P5 外に出す前に見せる

- **共有・書き出し**：バンドルに input/・config/・tests/ のファイルが入るときは、一覧を見せて外せるようにする（既定は input/ を外す）。P1 の印のある変数の初期値は、秘密と同じく含めない。
- **AI チャットに送る文**：メールアドレス・電話番号・郵便番号・マイナンバー・カード番号らしい文字があれば、送る前に「個人情報らしい文字があります。送りますか？」と確かめる（止めはしない）。
- **AI に渡ったもの**：Studio に「AI が読んだもの」一覧（どのツールで、どのフロー・ファイル・画面を、いつ）。`audit/mcp.jsonl` にすでにある記録を見せる。
- 理由：パターン検出は誤検出・取りこぼしがあるので、止める根拠ではなく「気づくきっかけ」にとどめる。

### P6 拡張機能に印のある値を渡す前に確かめる（後回しでよい）

- P1 の印のある値を拡張機能に渡すのは、シークレットと同じく「使ってよい先」に `plugin:<名前>` を許可したときだけ。
- 理由：拡張機能は外へ送れるので本来は要るが、拡張機能はまだ使う人が少ない。P1 のあとで足す。

### P7 利用の決まりを docs に書く

- AI の提供元の選び方（学習に使わない契約、会社の契約のある AI を使う）、Studio の外の AI クライアントでは Shikigami の外のファイルも読めること、共有ワークスペースの見える範囲、管理サーバーのファイルの置き場所。
- 理由：作りで抑えられない部分を正直に書いておくと、会社に入れるときの説明資料になる。

## 4. 推すもの

**P1 → P2 → P4** の順。P1 と P2 で「AI に普通の個人情報が届く」と「記録に残る」の両方を同じ印で抑えられ、P4 で残る期間が決まる。P3 は効果が大きいが Studio の作業が多いので、P1・P2 のあとに見本データの作り方を決めてから。P5 の書き出しの確認は小さいので P1 と一緒に入れてもよい。

## 5. やらないこと

- 値を見て自動で個人情報を見分けて伏せる（誤検出で業務が止まる、取りこぼしで安心させてしまう）。気づかせる用途（P5）だけにする。
- 記録の暗号化（PC を使える人は鍵も使えるので、効果のわりに重い）。保持期間と伏せ字で抑える。

## 6. 決めたこと（2026-11-08）

- **作った**
  - P1：変数の `personal: true`。伏せ方は秘密と同じ `***`（形だけ見せる「‹個人情報 12 文字›」はやめた。伏せ字が 2 種類になると覚えることが増え、しくみも 2 つ要るため）。実行の中では秘密と同じ扱い（伏せ字の対象に値の各部分を足す）なので、写した先・作った文・エラー・通知・管理サーバー・`get_run_logs` でも伏せる。一時停止中の値も `***` で、書き換えもできない（秘密と同じ）。初期値は書けるが、書き出し・「AI に渡す用にコピー」・実行からのテストケース保存では外す。
  - P4：`records.keepDays` の既定を 90 日に（`0` でずっと残す）。フローの `logs/` の実行ログと失敗時の画面にも効かせた（名前の日付で判断）。
- **作らなかった**：失敗時の画面で個人情報の欄を黒く塗る（P4 の一部。画面のどこに値が出ているかを確実に知る方法がなく、`records.failureScreenshots: false` で足りる）、`test_step`・`inspect_page` の結果の伏せ字（変数を通らない）、P2・P3・P5・P6。P7 は secrets.md の「個人情報」に対象外として書いた。
