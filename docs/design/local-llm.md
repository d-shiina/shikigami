# PC の中で動く AI でフローを組めるか（試験の記録）

結論（2026-11-12、Daiki 判断）：**見送り**。事務の PC（GPU なし、メモリ 8GB が多い）で動く大きさの AI では、ゼロからフローを組む用途に届かない。AI の契約がない会社向けの埋め込みは、PC の中で動く AI ではやらない。

## 何を試したか

- 背景：Claude などの契約がない会社でも AI でフローを組めるように、無料で配れてデータが外に出ない「PC の中で動く小さな AI」を同梱できないか。
- 環境：GPU なし、4 コア（Xeon 2.3GHz）、メモリ 16GB。事務 PC 相当として使用。llama.cpp（llama-cpp-python 0.3.36）で CPU 実行。
- 組み方：今の MCP をそのまま渡すと、ツールの説明と案内文だけで約 2.8 万トークン（ツール 2.3 万、案内文 0.4 万）あり、この速さでは読み込むだけで 10 分前後かかる。そこで SpellSheet 側が手順を仕切る形にした。
  1. ノードの種類を一覧から選ばせる（出力は選択肢だけに文法で縛る）
  2. 選んだ種類の設定の書き方・例・関数一覧・フローの例を渡し、フロー全体を JSON で書かせる（フローの形を JSON Schema の文法で縛る）
  3. `validate` のエラー（hint つき）と試しに動かしたときのエラーを返して直させる（最大 3 回）
- 課題：代表的な業務 6 本。正解のフローを先に書いて、判定が通ることを確かめた。
  - T1 請求書 CSV の合計と 10 万円以上の一覧
  - T2 受注 CSV から未出荷だけを CSV に書き出す
  - T3 Excel の売上を支店別に合計して Excel に書き出す
  - T4 input の PDF を「済_」を付けて output/請求書 にコピー
  - T5 点数で A・B・C に分けて CSV に書き出す
  - T6 Web の受注一覧を Excel へ（ブラウザは動かさず、構造だけ判定）

## 結果（Qwen3.5 4B Q4_K_M、2.7GB、Apache 2.0）

候補の中でいちばん小さい（8GB の PC で動かせる大きさの）もの。4 本測ったところで止めた。

| 課題 | 結果 | 直し | かかった時間 |
|---|---|---|---|
| T1 請求書の集計 | 正解 | 0 回 | 3 分 |
| T2 未出荷の抽出 | 検証が通らない | 3 回 | 11 分 |
| T3 Excel 支店別の集計 | 検証が通らない | 3 回 | 11 分 |
| T4 PDF の整理 | 動くが何もコピーしない | 1 回 | 4 分 |

- メモリは最大 6.7GB 使った（モデル 2.7GB＋作業領域）。8GB の PC では Excel やブラウザと同時に動かせない。
- 生成は毎秒 5〜7 トークン程度。1 回の書き直しに 2〜3 分。
- 間違い方：
  - T2：`variable.set` の `params.name` の代わりに `saveAs` を書き、「name が必須」の hint を 3 回返しても同じ間違いを繰り返した。
  - T3：`excel.writeRange` の `values` に見出しの行と `{{ 結果 }}` を混ぜた配列を書き、直せなかった。
  - T4：コピーのノードを書き忘れ、件数を数えるだけのフローになった。検証も実行も通るので、人が中身を見ないと気づけない。いちばん危ない失敗。

## 測らなかったもの

16GB の PC 向けの Qwen3.5 9B（5.7GB）、gpt-oss 20B（12.1GB、一度に動く部分が小さく速い見込み）、Gemma 4 E4B、Granite 4.2 3B、Ministral 3 8B（いずれも Apache 2.0）。事務の PC は 8GB が多く、16GB 向けで組めても導入の判断が変わらないため、試験はここで止めた。

## また検討するときのために

- PC の性能が上がる（NPU つきの PC が事務にも行き渡る）か、4B 前後で今の 9B〜20B 並みの AI が出たら、同じ課題で測り直す。試験の道具（課題・判定・正解のフロー・組ませる手順）は残してある。
- 埋め込むなら、今の MCP をそのまま渡すのではなく、SpellSheet が手順を仕切り、AI には文法で縛った JSON だけを書かせる形になる。小さい AI の決まった間違い（`variable.set` に `saveAs` など）は、SpellSheet 側で機械的に直す余地がある。
- ゼロから組ませるのではなく、「日付や URL を変える」「フローを説明する」のような小さい仕事なら、小さい AI でも足りる見込み（未検証）。
- AI の契約がない会社への別の道は、本体はそのままで AI だけ有料の別サービスにする案（有料プラグインと同じ考え方）と、無料枠のある AI（Gemini の API キーなど）を使う今の道。
