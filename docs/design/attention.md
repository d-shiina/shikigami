# 人の操作待ちを知らせる

実行が人を待ち始めても（ブラウザでのサインイン・スマホでの承認、エラーでの一時停止、AI からの承認やログイン情報の依頼）、Writer・Runner が他のウィンドウの後ろにいると、窓に出る「操作を待っています」の帯は見えない。フローはブラウザや業務アプリを前面に出して操作しているので、Writer が後ろにいるのがふつうの状態でもある。そこで、**待ち始めた瞬間だけ**、窓の外から知らせる。

## 手本にしたもの

| 製品 | 取り入れたこと | 取り入れなかったこと |
| --- | --- | --- |
| Teams | チャットや着信は、タスクバーのボタンの点滅と Windows の通知。通知を押すとその画面が前に出る | 着信の画面を最前面に出し続けること（電話ほど急がない） |
| Outlook | アラームは窓が後ろにいても気づける形で出す | アラームの窓を最前面に出すこと（フローが操作中の画面を隠し、入力を奪う） |
| Visual Studio | ブレークポイントで止まったら知らせる。ステップ実行（F10）は自分で押したので知らせない | 自分の窓を勝手に前面へ出すこと（Windows もほかのアプリからの前面化を止める） |
| Windows のガイドライン | 「注意が要るが、作業を止めるほどではない」ことはタスクバーの点滅、離れていても伝えたいことは通知。点滅は窓に戻ると止まる | ― |

## 何を出すか

窓が前にあるときは何も出さない（窓の帯で分かる）。後ろにあるときだけ、待ち始めた瞬間に次の 2 つ。

1. **タスクバーのボタンの点滅**：Windows の標準（`FlashWindowEx`、窓に戻るまで続く）。
2. **Windows の通知**：「「経費精算」が操作を待っています」＋何を待っているか（例：「ブラウザでサインインしてください」）。押すと、待っている窓（Writer か Runner）が前に出る。約 25 秒画面に出て、その後は通知センターに残る。待ちが終わったら通知センターからも消す。集中モード（応答不可）なら Windows が出さない。

フォーカスは奪わない。最前面の帯も出さない（フローが操作している画面の上に重なり、クリックや入力を邪魔するため）。

| 待ち | Writer | Runner | Worker（無人） |
| --- | --- | --- | --- |
| ブラウザでの手作業（`browser.waitForHuman`）・サインイン（`browser.oauth`） | 点滅＋通知 | 点滅＋通知（Runner にも帯を出す） | `notify` の `on` に `waiting` があれば Teams・Slack などへ |
| ダイアログ（`dialog.*`） | 出さない（ダイアログ自体が最前面に出る） | 出さない | 同上（無人では誰も答えないため） |
| エラーで一時停止 | 点滅＋通知 | ―（Runner は一時停止しない） | ― |
| ブレークポイントで一時停止 | 点滅＋通知 | ― | ― |
| ステップ実行・「一時停止」で止まった | 出さない（本人が押した） | ― | ― |
| AI からの承認・ログイン情報・部品の指定の依頼 | 点滅＋通知 | ― | ― |
| AI の単体実行（`test_step`）の `browser.waitForHuman` | 点滅＋通知（「AI がブラウザでの操作を待っています」のカード） | ― | ― |
| AI の変更の確認待ち | 出さない（実行は止まっていない。開いたときの紙のレポートで足りる） | ― | ― |

Worker は人がいない前提なので、PC の画面には出さず、スケジュールの終わりを知らせる `policy.json` の `notify` と同じ送り先に送る。既定（`["failed"]`）は変えない：だれも来なければ時間切れで失敗し、いつもどおり `failed` で知らせる。

## しくみ

- ランタイムの `humanActionRequired` イベントに `dialog`（その手順が自分の窓を最前面に出す）を足した。画面はこれを見て、ダイアログのときは知らせない。
- 画面（`lib/attention.ts`）が「今なにを待っているか」を名前（タグ）付きで決め、タグが変わった瞬間だけ `call_attention` を呼ぶ。待ちが終わると `clear_attention` で点滅を止め、通知を取り下げる。AI の依頼が 1 件片付いて残りがあるだけのときは、もう一度は鳴らさない。
- `call_attention`（`src-tauri/src/attention.rs`）は窓が前にあれば何もしない。通知は WinRT の `ToastNotification`。表示名とアイコンは、インストーラーが付けるスタートメニューのショートカットの AppUserModelID（`dev.shikigami.studio`）から出る。インストールしていない開発用ビルドは PowerShell の ID を借りて出す。
- Worker と `spellsheet run` は `notify::WaitWatch` でイベントを見て、待ち始めたら `notify_waiting` で送る。

## AI の単体実行の手作業待ち

AI がノードの単体実行（MCP の `test_step`）で `browser.waitForHuman` を動かすと、AI は人がブラウザで操作を終えるまで返事を待つ。実行は MCP サーバーの中にあって Writer の実行ではないので、Writer の「操作を待っています」の帯は出ない。そこで部品の指定（`ask_user_to_pick`）と同じ `picks/` のファイルで Writer に知らせる（`kind: "human"`）。

- Writer はカード「AI がブラウザでの操作を待っています」を出す。「終わりました」を押すと、目印（`until`）が出ていなくてもノードを終える。AI が当て推量した目印が実際の画面と合わないとき（ログイン後のダッシュボードの見出しの名前が違う、など）も、人が先へ進められる。AI には、人が終わらせたことと、そのときの画面が返り、目印を直すよう伝える。
- 「待つのをやめる」は待ちだけを止める。ブラウザは閉じない。AI には止められたことが返り、チャットで人に続け方を聞くよう伝える。
- 単体実行の待ちは既定 5 分、長くても 10 分。時間切れでも、そのときの画面と目印の見直しを AI に返す。
- AI の側で呼び出しをやめたとき（止めるボタン・時間切れ）は、実行も止め、ブラウザの中の待ちも終える。
- 待っている MCP サーバーは数秒ごとにファイルを触る。AI ごと止められて触られなくなったファイルは 20 秒で消えるので、カードが残り続けない。

AI の止めるボタンは AI のプログラムごと止めるので、そのとき AI が開いたブラウザも閉じる。待ちだけを止めたいときはカードの「待つのをやめる」を使う。
