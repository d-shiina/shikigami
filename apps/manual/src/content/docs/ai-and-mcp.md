SpellSheet では、フローを作るときに AI を使えます。使い方は 2 通りあります。どちらも、AI が SpellSheet の MCP サーバーを通してフローを読み書きします。

| 使い方 | 向いているとき |
|---|---|
| **Writer の AI チャット** | いちばん手軽です。Writer の中で頼んで、その場で確かめます |
| **ふだん使っている AI ツールから（MCP）** | Claude Code・Codex・Cursor などを日ごろ使っていて、そこから頼みたい |

どの方法でも、AI が作った内容は「確認待ち」で人が確かめるまで、無人では動きません。

## Writer の AI チャット

1. 上の帯の「AI チャット」を押します（<kbd>Ctrl</kbd>+<kbd>J</kbd>）。
2. 初めてのときは「AI を使う準備」が出ます。使う AI を選び、「（AI の名前）をインストールする」を押します。あなたのユーザーフォルダーに入り、管理者権限は要りません（1〜2 分）。
3. 終わるとサインインの画面が出ます。ブラウザでサインインし、表示されたコードを求められたら貼り付けます。

選べる AI と、料金のかかり方は次のとおりです。

| AI | アカウント |
|---|---|
| Claude Code | Anthropic の AI。あなたの Claude のアカウントで動き、料金もそのアカウントにかかります |
| OpenAI Codex | OpenAI の AI。あなたの ChatGPT のアカウント（Plus・Pro・Business など）で動きます |
| Gemini CLI | Google の AI。あなたの Google アカウントで動きます（無料で使える回数があります） |
| GitHub Copilot | GitHub Copilot を契約している GitHub アカウントで動きます。会社で Copilot を使っている人向けです |

使う AI はあとから「設定」→「AI」の「使う AI」で変えられます。会話は AI ごとに続きます。

### チャットの使い方

- 下の欄に頼みたいことを書き、<kbd>Ctrl</kbd>+<kbd>Enter</kbd> で送ります。
- ノードを選んだまま送ると、そのノードについての依頼になります。
- AI の作業中に送ると、今の作業を中断して割り込みます。
- 「新しい会話」で、別の話題を始めます。前の会話は「以前の会話」から開けます。

## ふだん使っている AI ツールに登録する（MCP）

Claude Code・Codex・Cursor・Gemini CLI・GitHub Copilot は、**MCP** という仕組みで SpellSheet につながります。登録すると、その AI ツールから「受注システムから未出荷の注文を集めるフローを作って」と頼めて、変更はそのまま Writer に出ます。

登録は AI ツールごとに一度だけです。SpellSheet を更新しても登録し直す必要はありません。

1. Writer の「設定」→「AI」→「MCP サーバーの登録」を開きます。
2. 登録する AI ツールを選びます。
3. **Cursor** のときは「Cursor に追加」を押します。Cursor が開いて、追加してよいか確認されます。
4. **ほかの AI ツール**のときは、表示されたコマンドを「コピー」し、ターミナル（PowerShell）に貼り付けて一度だけ実行します。例（Claude Code）：

```powershell
claude mcp add --scope user spellsheet -- "<SpellSheet の場所>\spellsheet.exe" mcp
```

コマンドには、この PC に入っている SpellSheet の場所が入った状態で表示されます。

:::tip[Claude Code のプラグイン]
Claude Code では、MCP の設定とフローの作り方を教えるスキルをまとめた Claude Code のプラグインも使えます（Writer のプラグインとは別のものです）。Claude Code で `/plugin install spellsheet --marketplace spellsheet/spellsheet` を実行します。
:::

AI ツールがあなたの PC で SpellSheet を操作するとき、何をしたかは監査の記録に残ります。

## 実行の許可

「設定」→「実行の許可」で、フローが触れてよい先と、AI が人の承認なしにしてよいことを決めます。Writer・AI・スケジュールのどこから実行しても、同じ設定が効きます。

| 項目 | 内容 |
|---|---|
| アクセスを許可するサイト | 1 行に 1 つ。例：`https://order.example.co.jp`、サブドメインすべては `https://*.example.co.jp`。空欄ならすべて許可します |
| 起動を許可するアプリ | 1 行に 1 つ。例：`C:\Program Files\Billing\billing.exe`、フォルダーを問わない場合は `notepad.exe`。空欄ならすべて許可します |
| AI の操作の承認 | 「フローの実行」「ノードの単体実行」「フローの削除」ごとに、**承認なしで許可**・**承認が必要**・**禁止** を選びます |

AI の操作は、影響の大きさで 3 つに分かれます。

| 影響 | 例 | 既定 |
|---|---|---|
| 影響なし | 変数・ログ・制御 | 承認なしで許可 |
| 画面操作 | クリック・文字入力 | 承認なしで許可 |
| 外部に影響する操作 | ファイルの削除や移動、外部への送信、プログラムの実行 | 承認が必要 |

「承認が必要」の操作を AI がしようとすると、Writer の上部に「AI が承認を求めています」と出ます（[AI の変更を確認する](../review/#ai-が承認を求めてきたとき)）。

開いているフローだけに「AI による実行」「無人実行」の決まりを付けることもできます。ワークスペース全体の設定より緩くはなりません。
