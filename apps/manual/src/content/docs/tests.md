---
title: テストケース
description: フローのフォルダーの tests の役割と、直したあとに前と同じ結果になるかをまとめて確かめる方法。
---

フローを直したあと、「前と同じ結果になるか」を毎回手で確かめるのは大変です。**テストケース**を残しておくと、ボタン 1 つで全部を流して確かめられます。

テストケースは「この入力で実行すると、こう終わって、出力はこうなる」を書いた小さなファイルです。フローのフォルダーの **`tests/`** に、1 件 1 ファイルで入っています。

```text
flows/<フロー>/
  flow.json
  input/
  tests/
    3支店の合計.json
    フォルダーが無い.json
```

ファイル名（`.json` を除いた部分）がテストケースの名前です。

:::note[tests フォルダーはいつ使われる？]
- Writer の下のパネルの「テスト」で「すべて実行」を押したとき
- 確認待ちのレポートで、AI の「期待する結果」を「実行して確認」したとき（AI が書いた期待する結果も、このフォルダーのテストケースです）
- AI がフローを直したあと、自分で結果が崩れていないかを確かめるとき

スケジュールや Runner でふだん実行するときには使いません。消してもフローは動きますが、直したあとの確かめができなくなります。
:::

## 作る

いちばん簡単なのは、うまくいった実行をそのまま残す方法です。

1. フローを実行して、結果が正しいことを確かめます。
2. 下のパネルの「テスト」を開き、「この実行をテストケースとして保存」を押します。
3. 名前を付けて「保存」を押します。

その実行の入力・終わり方・出力が、期待する結果として保存されます。エラーで中断した実行なら、エラーの種類と止まったノードが期待になります（「このファイルが無いときはエラーで止まる」のような確かめ方ができます）。

:::caution
シークレットの入力・出力と、長すぎる値は保存しません。保存したときにそう表示されます。
:::

## 流す

下のパネルの「テスト」で「すべて実行」を押すと、作業中の内容で 1 件ずつ実行し、結果を並べます。

| 表示 | 意味 |
|---|---|
| 期待どおり | 終わり方と、書いてある出力がすべて同じでした |
| 期待と違う | どこがどう違うかが出ます（例：「出力『total』 期待 3 実際 4」）。エラーで止まったときは、止まったノードへ移れます |
| 未実行 | まだ流していません |

- 1 件だけ流すときは、その行の「実行」を押します。
- 実行中に「中止」を押すと、今のケースを止め、残りは流しません。
- テストでも、フローは本当に実行されます。ブラウザや業務システムを操作するフローは、テスト用のフォルダーやテスト環境を入力で渡すようにしてください。
- テストの実行も、ふだんの実行と同じく記録に残ります。

## 何を比べるか

比べるのは、ケースに**書いてあるものだけ**です。

- 出力を増やしても、書いていない出力は見ないので、ケースは壊れません。
- 値が表やまとまりのときは、書いてある項目だけを比べます。
- 一覧は件数が同じで、1 件ずつ同じ決まりで比べます。
- 数は値で比べます（`3` と `3.0` は同じ）。

## 中身を直す

期待する値を変えたいときは、左の「プロジェクト」から `tests/` のファイルを開いて書き換えます。中身は次のような形です。

```json
{
  "description": "input の 3 支店の CSV を合計する",
  "inputs": { "folder": "input" },
  "expect": { "status": "succeeded", "outputs": { "branchCount": 3, "grandTotal": 73050 } }
}
```

| 項目 | 意味 |
|---|---|
| `description` | 何を確かめるケースか。確認する人に向けて業務の言葉で書きます |
| `inputs` | 入力の値。書かなかった入力は初期値のまま |
| `expect.status` | 終わり方：`succeeded`（完了）・`failed`（エラーで中断）・`cancelled`（中止） |
| `expect.outputs` | 確かめる出力と、その値 |
| `expect.errorCode` | `failed` のとき、エラーの種類（例 `FILE_NOT_FOUND`） |
| `expect.errorStep` | `failed` のとき、止まるはずのノードの ID |

## AI に頼むとき

AI にフローを直してもらうときは、「テストケースを足して、全部通るまで直して」と頼むと、AI が直すたびに前の結果が崩れていないかを自分で確かめます。

## コマンドで流す

バッチファイルや CI で確かめたいときは、コマンドでも流せます。1 件でも違うと終了コードが 1 になります。

```powershell
spellsheet test <フローの ID>            # 確定版で全部のケース
spellsheet test <フローの ID> --draft    # 作業中の内容で
```

テストケースは、フローを[ファイルに書き出す](../share/)ときにも一緒に入ります。
